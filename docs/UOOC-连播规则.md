# UOOC 自动连播 —— 切章节规则（待你审核）

> 这份文件描述的是**构建号 62 那一刻代码的真实行为**，不是设想。
> 对应源码：`src/sites/uooc/catalog.ts`（目录推进器）、`src/sites/uooc/video.ts`（节奏与护栏）、
> `src/sites/uooc/quiz.ts` + `quiz-return.ts`（测验来回）。
> 有任何一条你不认，直接说编号，我改。
>
> **构建号 64 的三处修订**（依据用户 m01255 给的 1.4.1 页面采样）：
> 1. **扫描起点改成记「元素」而不是 id** —— 第三层「点」里的附件，站点给的 `source.id`
>    是 **0**（同一份采样里 `resources: [{id:'0', type:50}]`），一节里有多个这种附件时
>    按 id 定位永远落在第一个上，又是一个死循环。现在记 `lastClickedEl`，
>    `pool.indexOf(el)` 天然唯一。起点优先级：**上一轮点开的元素 > hash 的 resourceId > 上游给的 id**。
> 2. **本节没有直接资源时，先点开里面的子目录节点**（第三层「点」）。
> 3. 「资源项」的选择器早前已放宽为 `[ng-click^="goSource("]` —— 这份采样验证了它是对的
>    （`resourceItem: 1` / `resourceItemStrict: 0`）。
>
> **实测到的三层目录结构**（两版都有，类名不同）：
> | 层 | ng-repeat | 标题元素 | 资源 |
> | --- | --- | --- | --- |
> | 章 | `chapterItem in chapterList` | 新 `div.level_1_title` / 旧 `div.basic.chapter` | — |
> | 节 | `sectionItem in chapterItem.children` | 新 `div.level_2_title` / 旧 `div.basic` | `source in sectionItem.unitSource` |
> | **点** | `pointItem in sectionItem.children` | 新 `div.level_3_title`（在 `ul.level_3` 里）/ 旧 `div.basic`（在 `ul.rank-3` 里） | `source in pointItem.unitSource` |
>
> 标题指令一律是 `ng-click="toggleChapter(xxxItem)"` +
> `ui-sref="main.chapter(.section)(.point)({...Id})"`；**新版章 / 节 / 点的 `li` 都没有 `id` 属性**，
> id 只在 Angular scope 里。
>
> **构建号 63 的两处修订**：
> 1. **扫描起点改为「两个都试」**：先试 hash 里的 `resourceId`，再试「上一轮真的点开的那个」。
>    只认 hash 会死循环 —— 多层目录里 hash 可能还留着**更早那个资源**的 id，而它已经不在
>    本节渲染出来的列表里，于是每轮都「从本节开头重新找」、反复点同一个视频（m01213 的日志）。
> 2. **「本层走完」改为按文档顺序找下一个目录节点**（见下面第 10 条），
>    从而支持「子目录 / 同级都没有下一项时上到上一层的下一个」。
>
> **构建号 62 的两处修订**：
> 1. **测验一律不点元素**（原来「已完成的测验」会走通用的「点开元素」分支，而新版那个
>    节点点下去会开新标签页）。现在：已完成的测验不打开、直接进统一出口；未完成的走
>    `quizUrlFor()` 整页跳；只有旧版（给不出地址）才退回点元素。
> 2. 资源项选择器从逐字等值的 `[ng-click="goSource(source, 'section')"]`
>    **放宽为前缀匹配** `[ng-click^="goSource("]`，并把读取资源对象的键从只认
>    `scope.source` 放宽为「先认 `source`，再按像不像资源对象兜一圈」——
>    用来兼容「资源挂在 1.4.1 / 1.4.2 这种更深一层」的课程（待验证）。

## 1. 什么会触发「往下走」

| 触发 | 代码位置 | 说明 |
| --- | --- | --- |
| 视频播完（`ended`） | `video.ts` `onMediaEvent` | 连播**唯一的自然入口** |
| 落在「看过一部分」的视频上一直没播起来 | `breakStall()` | 兜底，落点停着且进度>3s |
| 「这一项好了」的等待时间到 | `scheduleSwitch()` 的定时器 | 见 §3 |

**没有别的入口。** 你自己手点目录换集不会触发连播（不会接管你的操作）。

---

## 2. 一次「走一步」的完整判定顺序

`catalog.ts` 的 `stepForward(afterId)`，**只走一步就返回**，由调用方决定「等一下再来」还是收工：

| # | 条件 | 结果 |
| --- | --- | --- |
| 1 | 页面上没有 `angular` | `stop`（日志说明） |
| 2 | hash 解析不出 `chapterId` | `stop` |
| 3 | 目录里找不到这个章节点 | `stop` |
| 4 | hash 只到章（刚跨完章） | 点**第一节标题**（这一章没有节就点章标题）→ `rendered` |
| 5 | 当前章里找不到当前节 | 点一次章标题催它按需渲染 → `rendered`；**同一个节只催一次**，再找不到就 `stop` |
| 6 | 收集本节资源 | 优先「归属本节的资源项」；归属判不出来就退回全页（旧版只渲染当前节，全页就是本节） |
| 7 | 定扫描起点 | hash 里有 `resourceId` 就用它；否则用「上一轮真的点开的那个资源」，**但只在章 / 节都没变时才认** |
| 8 | 从起点往后逐项判 | 见 §4 |
| 9 | 本节扫完、一个资源项都没有 | ① 若这一节是**折叠**的（`sectionItem.hide === true`）→ 点一次节标题展开 → `rendered`；② 否则报 `blank` |
| 10 | 这一层扫完、**章内**还有下一个可点的目录节点 | 点它（按文档顺序取「当前项之后最近的目录节点」）→ `rendered` |
| 11 | 章内没有下一个目录节点了 | `chapter-end` |
| 12 | 其它异常 | `stop`（日志带原因） |

> **第 10 条是干嘛的**：目录可能是多层的（1.4 → 1.4.1 / 1.4.2 → 1.5）。
> 「当前项之后最近的目录节点」这个取法**天然就是**「同层还有就同层下一个，同层没了就是上层的下一个」，
> 不需要专门写「回上一层」的逻辑。它**只在当前章内找**，所以「止于本章」不受影响。
> 判据是「在章节点子树里、带 `ng-click` 或 `ui-sref`、且不在资源项内部」——不写死类名。

## 3. 「提醒 + 等 N 秒」是唯一的出口

```ts
scheduleSwitch(reason)   // video.ts
```

- **开关关着** → 直接返回，什么都不做。
- **已经在等了** → 直接返回（不重复提醒）。
- 否则：**右上角弹提醒** → 等 `切前等待` 秒（设置项，默认 **5**，范围 0~120，0 = 立刻切）→ 走下一步。
- 等完调用 `resumeAdvance()`：**先清掉 8 秒的 `advancingUntil` 锁**再走 ——
  那个锁是给「同一次点击被 `ended` 重复触发」兜底的，不清掉会把等待结束后的这一步吞掉。

**所有路径都汇到这里**：视频播完、文档/附件打开、已完成项、测验交卷、空白节、测验完成。

## 4. 逐项判定：什么样的资源会被怎么处理

从扫描起点往后，**第一个**命中的项决定这一步做什么：

| 资源情况 | 做什么 | 之后 |
| --- | --- | --- |
| **测验**且**未完成** | **整页跳去测验**（新版 `/exam/{tid}`）；旧版点元素（内嵌 iframe） | 见 §5 |
| 其余一切（含**已经完成**的） | **点开它** | 见下 |

点开之后的收尾：

| 点开的是什么 | 之后 |
| --- | --- |
| `finished === true`（不管什么类型） | `scheduleSwitch('已完成的X')` → 提醒 + 等 N 秒 |
| 视频且**未完成** | 不管，交给它自己播完 —— `ended` 会来触发 |
| 文档 / 附件且未完成 | `scheduleSwitch('已打开X')` → 提醒 + 等 N 秒 |

> ⚠️ **没有任何「跳过」分支了**（这是你 m01058 第 2 条的要求）。
> 唯一不再往前走的情况是上面第 9 条的空白节。

## 5. 测验的来回（同一个标签页）

```
学习页                         测验页（同一个标签页）
  │  把 returnUrl 写进 sessionStorage
  │  location.href = /exam/{tid}   ──────►
  │                                轮流判定（每秒一次）：
  │                                  ① 先见过「提交试卷」→ 之后它不见了（≥2 秒）
  │                                  ② 有题目容器、但提交/保存按钮都没有
  │                                     → 这是一张已交过的只读视图
  │  ◄──────  location.replace(returnUrl)
  │  sessionStorage 里 done=true
  → 触发 scheduleSwitch('测验已完成') → 提醒 + 等 N 秒 → 继续
```

- `returnUrl` 特意写成**那一项资源**的路由
  （`…/home/learn/index#/{cid}/{chapterId}/{sectionId}/{resourceId}/section`），
  这样跳回来时 hash 带着 `resourceId`，扫描起点不会退回本节开头（否则整节会被重放一遍）。
- 用 `location.replace` 而不是赋值：这趟是「替用户去了一趟又回来」，不在浏览器历史里留痕。
- **跨标签页通信已全部删除**（`quiz-signal.ts` 已删）：不再开新标签页、不再有
  `localStorage` + `storage` 事件那套、不再尝试关标签页。

## 6. 空白节（本轮的争议点）

「本节一个资源项都没渲染出来」时，按顺序试：

1. **折叠**（`sectionItem.hide === true`）→ 点一次节标题展开 → 继续。
   *这是旧版那个「空白页」的真因：数据里 `unitSource` 有 4 项，只是被 `ng-if` 藏起来了。*
2. 还是空 → 报 `blank`。调用方**重试 3 次**（每次 1.5 秒，共约 4.5 秒，给「刚点进去还没渲染完」留时间）。
3. 仍然空 → `scheduleSwitch('本节没有可看的内容')` → 提醒 + 等 N 秒 → **跳过这一节**。

⚠️ **已知缺陷**：新版「闯关模式」课程的内容挂在 `2.3.1 / 2.3.2` 这种**更深一层**里，
那一层的资源不属于 `sectionItem.unitSource`，会被上面第 3 步当成空白节跳过。
**需要一份闯关模式页面的 DOM 采样才能修**（`tools/dom-probe-uooc-blank-section.js` 已加了
I/J 两段专门 dump 深层的 `ng-repeat` 与可点节点）。

## 7. 跨章

`chapter-end` 时看设置项 **`连播范围`**：

- `止于本章`（默认）→ **停在这里**并打日志；
- `跨章继续` → 点下一章的标题（`[ng-click="toggleChapter(chapterItem)"]`）→ `rendered`，
  下一步会走 §2 第 4 条自动进这一章的第一节。

目录里没有下一章了 → 打「目录里后面没有资源了」，收工。

## 8. 护栏（防止失控）

| 护栏 | 值 | 作用 |
| --- | --- | --- |
| 单轮最多走几步 | 40 | 空节 / 页面异常时不会无限点 |
| 单轮最长多久 | 45 秒 | 同上 |
| 点击后的锁 | 8 秒 | 防 `ended` 重复触发导致连点 |
| `breakStall` | 落点 +12 秒仍在暂停且进度 >3s | 判为「看过的视频」，进等待 |
| 「节是折叠的」只点一次 | 按 章/节 去重 | 防点不开时来回点 |
| 「本节空白」只报一次 | 按 章/节 去重 | 防「空 → 提醒 → 等 → 再走一步 → 还是空」原地打转 |

## 9. 当前**不**参与判定的东西（你可能想改）

1. **`is_task`（任务点）完全不参与连播判定** —— 所有资源一视同仁地「点开 + 等 N 秒」。
   （数据层里它是准的：视频/测验 `true`，文档/附件 `false`。）
2. **不判断文档 / 附件有没有「完成」** —— 打开后只等 N 秒就走。
3. **不区分「看过一半的视频」** —— 一律点开，靠站点自己的续播位置播完。
4. **闯关模式（`2.3.1` 这种更深一层）不支持** —— 见 §6 的 ⚠️。
5. **不发任何额外请求** —— 完成状态只读 DOM / scope（进度上报是独立的开关，走 §10 之外）。
