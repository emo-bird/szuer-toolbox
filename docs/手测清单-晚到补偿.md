## 0. 这次改了什么（一句话）

**我们不再自己画课表了**（用户拍板：以站点绘制为主）。
课表由站点自己画，我们只做两件事：

1. **给自定义课程那一行的课名塞一个「自定义」标签** —— 站点拼卡片时不渲染任何数据属性、
   也不转义，所以标签只能塞进 `courseName` 这个文本字段（`<span class="sztb-bkxk-tt-tag" data-sztb-tt="1">自定义</span>`）。
2. **晚到补偿（v0.24 就有，本轮保留）**：普通刷新（暖缓存）下站点在 **75ms** 就把
   `teachingTime.do` 发出去了，而 Tampermonkey 把脚本投进页面要 200ms 之后 ⇒ 那条响应我们
   永远看不到，站点就只画它自己的 14 门课。发现「站点画完了、而我们没赶上」时，请站点自己的
   `CVQueryCurriculum.init()` 再请求一次（这一次必定经过我们的包装）。

**本轮删掉的**：旧版自绘那一整套（几何、派单表、读已选课程、冲突判色、同名去重、重画判据）
以及 🟢 【自绘课表】开关（**设置里现在只剩 6 个 🟢 开关**）。
**本轮没做**：「与已选课程冲突时整张卡描红框」（站点 class 写死，只能渲染后再加类）。

## 1. 前置条件

- [ ] 装的是**构建号 43**（悬浮窗【设置 / 状态】页，或 Console 里那行 `深大人工具箱 v0.1.0#43`）。
- [ ] 已登录 bkxk，且【自定义】里**至少有一门启用**的自定义课程（有星期几的那种，
      例如 `1-18周 星期一 3-4节 致理楼L1-707`）。
- [ ] 已把上一版脚本**卸载/关掉**，避免两份脚本同时接管。
- [ ] 准备两次刷新：**硬刷新** = `Ctrl+Shift+R`；**普通刷新** = `F5`。
- [ ] 知道去哪儿看日志：悬浮窗的 **【日志】** 标签页（模块日志不刷 Console）。

> 顺序很重要：**先做 #99 / #100（普通刷新）**，再做后面几条。
> 普通刷新是这条补偿存在的**唯一理由**；如果这次普通刷新恰好也没触发补偿，
> 请多重试几次（多按几次 F5）—— 站点那条请求抢在我们前面与否跟缓存冷热有关。

## 4. 通过判据

- 全部必测条目**达预期**即通过。
- 只要出现下面任意一条，无论其它条目是否通过，一律算**失败**：
  **「同一门课两份卡片」**、**「补偿那行反复刷屏」**、**「课名里的 `<` 把页面弄破版」**、
  **「自定义课程在课表里一个都没有且日志里没有补偿那一行」**。
- 「自定义课程在课表里一个都没有，但日志里有补偿那一行」算**可疑**：贴回日志，我来判是
  站点没画还是我们没认出来。

## 5. 回传三件套

失败时请贴回（缺一不可）：

1. **【日志】页全文** —— 从 `响应接管已安装` 那一行开始，直到你停下操作。
2. **该次现象的截图** —— 课表区（含列头）或悬浮窗对应页面。
3. 若与请求有关：F12 → **Network** 面板过滤 `teachingTime` 后的截图
   （要看得到**几条**请求、状态码、时间点）。

成功就回 `OK`。
