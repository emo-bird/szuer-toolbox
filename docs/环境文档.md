## 依赖安装（**必须带 `--ignore-scripts`**）

```pwsh
npm install --ignore-scripts        # ✅
npm install                         # ❌ npm error code EPERM, syscall 'spawn'
```

原因：esbuild 的 postinstall 会 `node install.js`，而 **DSH 沙箱禁止「node 用管道
spawn 子进程」**（见下「沙箱边界」）。加 `--ignore-scripts` 后 esbuild 仍能正常工作，
因为真正的 `esbuild.exe` 由 optionalDependencies 的 `@esbuild/win32-x64` 直接落地。

## 沙箱边界（实测，务必牢记）

**规则**：纯 JS 不受影响；**原生 exe 直接跑不受影响**；只有「node 用管道 spawn 子进程」
这一条路被堵死（EPERM）。

> ⚠️ **该限制随沙箱档位变化**：上表全部是在**受限档位**（`read-only` / `workspace-write`）
> 下实测的。切到 **`danger-full-access`** 后**命名管道解禁**，
> `sh.exe` 与 spawn 管道恢复正常（实测 `"C:\Program Files\Git\bin\sh.exe" -c "echo ok"` ✅ exit 0），
> `git filter-branch` 因此可用（见 `docs/开发文档.md` §9）。
> 换句话说：**「spawn EPERM」是档位问题，不是本机固有缺陷** —— 遇到时先确认当前档位。

| 试法 | 结果 |
|---|---|
| `npm install` | ❌ `spawn EPERM` |
| `npm install --ignore-scripts` | ✅ |
| 直接跑 `esbuild.exe --version` | ✅ |
| esbuild **JS API** | ❌ `Error: spawn EPERM at ensureServiceIsRunning` |
| `spawnSync(exe, args, { stdio: ['ignore', outFd, errFd] })` | ✅（fd 重定向） |
| `spawnSync(exe, args, { encoding: 'utf8' })`（走管道） | ❌ `err=EPERM` |
| `tsc.cmd --version` / `tsc --noEmit` | ✅（TS 启动器用 `stdio: 'inherit'`） |
| `git filter-branch --env-filter …` | ❌ `sh.exe: *** fatal error - couldn't create signal pipe, Win32 error 5`（受限档位）｜✅ `danger-full-access` 下正常 |

⇒ 结论：**`build.mjs` 必须用 `spawnSync` 调原生 `esbuild.exe` + fd 重定向**，
不能用 esbuild 的 JS API。

## 已知注意事项

- **npm 缓存**：本机默认 npm 缓存目录在沙箱外，故 `.npmrc` 里把 cache 指到工作区内
  的 `.npm-cache/`（已 gitignore）。registry 走 `https://registry.npmmirror.com`。
- **pwsh 坑**：双引号字符串里的 `$(...)` 子表达式语法会被 PowerShell 当命令执行
  （实测报 `IncompleteDollarSubexpressionReference` 或静默吞掉内容）。
  需要多断言校验时**写成 Node 脚本文件**（如 `tools/verify-build.mjs`）比在 pwsh 里堆表达式稳。
- **pwsh 花括号展开坑**：`git rev-parse 8d033f0^{tree}` 里的 `^{tree}` 会被 pwsh 当
  **花括号展开**吃掉，实报 `fatal: ambiguous argument 'dAByAGUAZQA=': unknown revision`
  （`dAByAGUAZQA=` 是被拆碎的 base64 片段）。
  ⇒ **凡涉及 `^{…}` 的 rev-parse 一律加单引号**：`git rev-parse '8d033f0^{tree}'`。
- **git 输出走 stderr 会被 pwsh 判成错误**：`git checkout` 成功时打印
  `Switched to branch '…'` 到 stderr，pwsh 会显示 `NativeCommandError` 并让
  `$LASTEXITCODE` 为 1。**别把这个 exit 1 当成命令失败**，要用后续查询核实真实状态。
- **commit message 用 here-string**：pwsh 里 `git commit -m "…$(…)"` 的 `$(...)` 会被执行，
  改用 `@'…'@` here-string 落临时文件 + `git commit -F`。
- **注释里的 glob**：中文注释里不要写带 `*/` 的 glob（如 `src/**/*.ts`），会提前闭合块注释。
- 本地模型卸载（`lean_agent` / workflow 的 `agent()`）依赖 LM Studio 保持运行且
  `ornith-1.5-9b-dsh-agentic-gpt-5.6-sol-distill` 处于加载状态；若 1234 掉线需重新启动。
- 抓包文件放 `local/capture/`（**不随 git**），处理流程见 preset 的 `scrape-toolkit` 技能：
  `flow_probe` → `flow_index` → `flow_slice` / `flow_extract` → `flow_replay`。
- 参考脚本与导出数据放 `local/reference/` 与 `local/export/`，同样不随 git。

## 本项目命令速查

| 命令 | 作用 |
|---|---|
| `npm run typecheck` | `tsc --noEmit`（覆盖 `src/` + `tests/`） |
| `npm test` | 纯函数冒烟（档 1），**196 用例**，约 0.93 s |
| `npm run build` | 生成 `dist/szuer-toolbox.user.js`（会**递增构建号**） |
| `npm run verify` | 产物自检 **24 项** |
| `npm run check` | 上面四步串起来 |

> ⚠️ **只核对基线、不想弄脏工作树时，别跑 `npm run check`** —— 它会递增
> `dist/.build-no` 并重写产物。用 `npm run typecheck` + `npm test` +
> `npm run verify` 三件即可。
> 另：「装了哪一次构建」以产物头部那行 `构建信息` 为准，**不要**以 `dist/.build-no` 为准
> （它不随 git，可能领先于产物里记录的号）。

测试直接跑 TS 源码（`node tests/run.ts`），靠 Node 24 的类型擦除，**不预编译**。
