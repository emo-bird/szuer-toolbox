  - ❌ `@match` 没命中 —— 用户实测 Tampermonkey 面板显示**脚本已正确匹配**；

## 2. 站点适配层接口约定【v0.5 定稿：已实现】

> 契约定稿于 `src/sites/types.ts`，以下为实际签名（与代码逐字一致）。

```ts
type RiskLevel = 'safe' | 'trace' | 'irreversible';   // 🟢 只读 / 🟠 留痕 / 🔴 不可逆

interface SiteAdapter {
  readonly id: string;                  // 'bkxk' | 'uooc'
  readonly name: string;                // 显示名
  readonly hosts: readonly string[];    // 命中哪些 host（决定是否注入）
  readonly pages: readonly string[];    // 命中后哪些页面「自动展开」；[] = 该站任意页
  readonly tabs: readonly TabRegistration[];
  readonly toggles?: readonly SiteToggleDef[];
  earlyInit?(ctx: SiteEarlyContext): void;   // 【v0.11 新增】启动期，document-start 时机
  init?(ctx: SiteInitContext): void;         // 挂载期，DOMContentLoaded 之后
}

// 【v0.11 新增】启动期上下文：此时 document.body 还不存在，**不允许碰 DOM**
interface SiteEarlyContext {
  readonly adapter: SiteAdapter;
  readonly url: URL;
}

interface SiteInitContext {
  readonly adapter: SiteAdapter;
  readonly isFeaturePage: boolean;
  readonly panel: PanelApi;             // collapse/expand/toast/confirm/activateTab
}

interface TabRegistration {
  readonly id: string;                  // 全局唯一，如 'bkxk:tasks'、'common:settings'
  readonly title: string;
  readonly order?: number;              // 升序，默认 1000
  readonly css?: string;                // 会被塞进 shadow root 的 <style data-tab>
  mount(root: HTMLElement, ctx: TabContext): void | (() => void);  // 返回值为卸载钩子
}

interface TabContext { readonly siteId: string; readonly host: PanelApi; }

interface SiteToggleDef {
  readonly id: string; readonly label: string; readonly desc?: string;
  readonly risk: RiskLevel; readonly default: boolean; readonly group?: string;
}
```

**分派规则**（`src/sites/registry.ts`，纯函数、有测试钉死）：

```
命中适配器 hosts            → 注入 + 悬浮球；再命中 pages → 自动展开
在 szu.edu.cn 下但未命中适配器 → 注入 + 悬浮球（仅公共标签页）
uooc.net.cn 及其子域         → 注入 + 悬浮球；进入功能页再自动展开
其它                        → 不注入
```

调试开关：URL hash 里带 `sztb-demo` 时强制注入 `demo` 适配器（仅开发期）。

**红线由代码兜底，不靠作者自觉**：
- 风险门禁**只有一处实现**（`src/common/core/settings.ts` 的 `isEnabled`）——
  未注册恒 `false`；**从未设置过时，只有 `risk==='safe'` 才取 `def.default`，
  🟠/🔴 一律强制 `false`**。
  **【v0.11 收紧】**：即便适配器给 🟠/🔴 写了 `default: true`，那也是**死数据**，
  只会在后来人读代码时造成「这功能默认是开着的」的错觉。
  所以 **`default` 也一律写 `false`**，并由 `tests/suites/sites-registered.test.ts`
  对每个真实适配器逐条断言（不变量：`risk !== 'safe'` ⇒ `default === false`）。
- 🔴 的二次确认由 UI 层在勾选时弹出（`src/common/ui/widgets/checkbox.ts`），
  取消则复选框回弹。**这个对话框严禁做成可跳过。**
- 所有出网请求经 `src/common/core/http.ts` 的**带优先级的串行队列**，
  间隔由 `src/common/core/limits.ts` 的 `LIMITS.intervalMs` 决定（默认 500ms）。
  **【v0.11】200ms 从硬下限降级为软提示**（需求文档 Q-AF）：低于它只 `log.warn`，
  **不改用户输入值**。`LIMITS.intervalMs.min = 0` 仅防负数与荒谬值。
- 日志只记路径不记 query（凭证不落盘，红线 N3）。
- 站点**不自己注册设置标签页**，只声明 `toggles` / `values`，由公共
  `common:settings` 标签页统一渲染。
  **【v0.12 修订】**：站点**可以**注册自己的设置标签页（bkxk 已这么做，见需求文档 Q-AG），
  但**必须**满足两个条件：① 标签 id 恰好等于 `settingsTabId(siteId)`（即 `<siteId>:settings`）；
  ② 渲染必须走共享组件 `common/ui/widgets/settings-form.ts` 的 `renderSiteSettings()`。
  公共设置页据此把该站点换成一行指引，否则同一个开关会出现两遍还能从两处改。
  这两条由 `tests/suites/sites-registered.test.ts` 的「站点设置标签页归属」套件钉住。
- **【v0.12】面板内按键不外泄**：`common/ui/panel.ts` 在 shadow root 的**冒泡阶段**
  对 `keydown` / `keypress` 做 `stopPropagation()`，只拦不外传、**不 `preventDefault`**。
  起因见需求文档 Q-AH：站点的 `banBackSpace`（挂 `document.onkeydown`）会因为
  Shadow DOM 把事件 `target` 重定向成宿主元素而判不出「这是输入框」，进而拦掉 Backspace。
  **改动这里要同时确认：捕获阶段的监听（如 `confirm.ts` 的 Esc）仍能收到按键、
  输入框自身的编辑行为未被 `preventDefault` 掉。**

`tabCss`、`src/sites/demo/index.ts` 的 `demoCss`、`src/sites/bkxk/list-style.ts` 的 `LIST_CSS`。

这一条自检就是为「header 承诺了站点、注册表却没登记」这类静默事故准备的（见 §1 教训二）。

**依赖方向铁律**（违反即为架构错误）：

1. `common/` **不得** import `sites/`；只能 `sites/ → common/`。
   需要站点信息的公共组件走**依赖注入**：`setSiteNameResolver(fn)`（设置页）、
   `setStatusProvider(fn)`（状态页）。
2. `sites/` 内各站点**互不 import**；跨站点数据走 `common/core/storage`。
3. 站点模块**不直接操作悬浮窗 DOM**，只通过 `TabRegistration` 声明式注册。
4. UI 完全自研，**不引入任何 UI 库**（Bonsai-kit 已否决，留档于 `docs/需求文档.md` §7.1.1）。

### 2.2 样式隔离【v0.4 定稿：混合方案】

| 范围 | 手段 |
|---|---|
| 悬浮窗本体（面板 + 所有标签页） | **Shadow DOM** |
| 注入站点页面内的元素（如插进章节列表的小按钮） | **前缀命名空间** + `all: initial` 重置 |

**对注册接口的硬性影响**：标签页在 Shadow DOM 内 ⇒ **不能依赖全局 CSS**。
`common/ui` 的标签页注册接口**必须同时接受样式**（例如
`registerTab({ id, title, mount(root, ctx), css? })`，由 `common/ui` 把 `css`
塞进 shadow root 的 `<style>`），否则站点模块写的标签页会没有样式。

站点专属的**注入元素**样式则相反：放在站点目录内、按前缀命名，**不进 shadow root**。

> 完整目录树见 `docs/需求文档.md` §10。

### 2.1.1 标签栏的顺序、分组与记忆【v0.12 新增】

**顺序由 `src/common/ui/tab-order.ts` 的 `planTabOrder()` 唯一决定**，
`TabView` 只负责渲染它的结果 —— 这一层刻意做成纯函数（不碰 `document`），
因为 `TabView` 在 node 下测不了，而顺序规则又很容易被写错。

| 规则 | 内容 |
|---|---|
| 分组 | `siteId === COMMON_SITE_ID('common')` ⇒ 公共组，其余 ⇒ 站点组 |
| 组间 | **站点组在前，公共组在后**（与 `order` 数值无关，写 999 也翻不过去） |
| 组内 | 按 `TabRegistration.order` 升序；缺省 `1000`；**稳定排序**，同 order 保持注册顺序 |
| 分隔线 | 两组**都非空**时在交界处插一条 `.sztb-tab-sep`；只有一组时**不插** |

- ⚠️ `order` 的语义**已从「全局权重」变为「组内权重」**。
  此前靠「公共占 0–99、站点从 100 起」的注释约定，写错会**完全静默**地错位。
- ⚠️ `tabs.ts` 的 `setTabs()` 入参是 `TabOrderInput`（含 `siteId`）而**不是**裸的
  `TabRegistration`。`panel.ts` 原来把 `siteId` 丢掉了（只把 `e.tab` 传下去），
  这正是分组做不了的原因 —— **别再改回去**。
- ⚠️ 分隔元素用 `class="sztb-tab-sep"`（不是 `sztb-tab`）。`activate()` 用
  `querySelectorAll('.sztb-tab')` 遍历标签按钮，class 选择器按**独立 token** 精确匹配，
  所以不会命中它。

**上次停留的标签页**：键为 `ui:active-tab:<页面>`，**按页面分键**【v0.14 改口径】，
与 `ui:panel-pos` 等全局键**故意不一致**（位置是「我的面板在哪」，标签是
「我在**这个页面**看哪一页」）。

`<页面>` 由 `pageScopeOf(entries)` 给出：**有站点标签页就取第一个站点组**
（多个站点同时命中时按 `planTabOrder` 的组内先后取第一个 —— 确定性的，不随注册顺序抖），
一个站点标签页都没有（UOOC 现状、普通网页）就是 `'common'`。

⚠️ **口径变迁，别再往回改**：v0.12 按「标签页自己归属的站点」分键、v0.13 又让
「站点组优先」参与恢复 —— 这套组合在用户实测里当场翻车：

| 步骤 | 旧口径（v0.12 / v0.13） | 现在（v0.14） |
|---|---|---|
| 在本科选课页面点【日志】（公共标签页） | 写进 `ui:active-tab:common` | 写进 `ui:active-tab:bkxk` |
| 刷新该页面 | 先去读 `ui:active-tab:bkxk`，里面的旧值把它**抢回去** | 只读 `ui:active-tab:bkxk`，值就是 `common:log` ⇒ 停在【日志】 |

恢复规则此时只剩两条（`resolveActiveTab(entries, stored)`）：

| 次序 | 内容 |
|---|---|
| 1 | 读本页面的**那一个**键 `ui:active-tab:<pageScopeOf(entries)>` |
| 2 | 值非空**且**该 id 在当前标签集里 ⇒ 采用；否则返回 `null`，调用方回退 `planned[0]`，且**不写盘** |

**落盘：只有用户点击才写**（`panel.ts` 的 `restoring` 闸门）：

1. 用户点标签页 ⇒ `remember(tabId)` 写进**本页面**那把键（`pageScopeOf`），
   与点的是站点标签页还是公共标签页**无关**；
2. `setTabs()` 内部那次自动激活**不写** —— 它只是把记忆恢复出来，不是新选择；
3. 存的 id 已失效 ⇒ 只回退显示、**不写盘**，等用户下次点击自愈。

此外 `panel.ts` 用内存变量 `currentTabId` 记住当前标签页：只有**首次**建标签集
（`currentTabId === null`）才查 storage，之后重建（适配器二次注册、`setTabs` 再调）
沿用内存值，免得把用户从当前页拽回存储里的旧值。

⚠️ 两个坑**都让整条功能静默失效**，都是手测暴露后修掉的，别改回去：

- **`tabs.ts` 的初始选中不能看 `this.current`**：`setTabs()` 第一行的
  `destroyTabs()` 刚把它清成 `null`，那个 `this.current !== null` 分支是**死代码**，
  于是选中恒等于 `planned[0]` —— 曾经的实现就是这样，**记忆只写不读**，
  现象是「怎么点、刷新后都回第一个标签页」。现在改成接受 `preferredTabId` 入参：
  `preferredTabId !== null && this.mounted.has(preferredTabId) ? preferredTabId : planned[0]`。
- **落盘闸门不能用「存的值是否等于当前值」判断**：
  `shouldRememberActive()` 已删除。它在「首次访问」时两者不等 ⇒ 判为「不记」⇒
  此后用户所有点击都被 `if (!persist) return;` 丢弃，键值**冻死在第一次写入**
  （UOOC 这种只有公共标签页的页面最明显）。

档 1 用例：`tests/suites/tab-order.test.ts`（分组、组内稳定序、缺省 order、
分隔线位置、空输入、不改入参、记忆键结构、页面 scope 4 条、恢复与失效 6 条）。
⚠️ 该文件的 fixture id 必须与**真实注册 id** 一致：公共标签页 id 带 `common:` 前缀
（`common:settings` / `common:log` / `common:login` / `common:status`），
id 写错的 fixture 会让用例「看起来在测恢复、其实两条都是空键」而照样通过。
渲染正确性只能走档 3 手测。

### 2.1.2 悬浮球与关闭键同坐标（双向）【v0.13 新增，v0.14 补展开方向】

几何全部在 `src/common/ui/panel-geometry.ts`（**纯函数、零 DOM**），
`panel.ts` 只负责把 `window.innerWidth / innerHeight` 喂进去、把结果写进 style。
抽出来的理由：`panel.ts` 依赖 `document`、在 node 下测不了，
而这里的往返一致性最容易被改 CSS 时**静默**破坏（只表现为球偏几个像素）。

球**没有自己的存储键**：旧键 `ui:ball-pos` 已停用（**不再读取，也不主动删除**，
用户机器上可能还残留一个死值）。两个方向都现算：

```
收起：球.left = 面板.left + 面板.width − COLLAPSE_BTN_INSET(21) − BALL_SIZE(44)/2
     球.top  = 面板.top  + HEAD_HEIGHT(37)/2                    − BALL_SIZE(44)/2
展开：面板.left = 球.left + BALL_SIZE(44)/2 + COLLAPSE_BTN_INSET(21) − 面板.width
     面板.top  = 球.top  + BALL_SIZE(44)/2 − HEAD_HEIGHT(37)/2
```

两个函数互为逆运算，往返恒等（`panelPosFromBall(ballPosFromPanel(p, size), size) === p`）
有档 1 测试钉住。

两个常量是**从 CSS 反推的**，改样式必须同步改常量，否则球会偏（差 1px 也看得出来）：

| 常量 | 值 | 对应 CSS |
|---|---|---|
| `HEAD_HEIGHT` | 37 | `.sztb-head` 上下 `padding 8px` ×2 + `.sztb-iconbtn` 高 22px |
| `COLLAPSE_BTN_INSET` | 21 | `.sztb-head` 的 `padding-right: 10px` + 按钮宽 22px 的一半 |

**展开方向**（用户 m00593 实测后要求：「球被移动时，展开悬浮窗时，要把悬浮窗关闭按钮
移动到球的位置，若和页面边界冲突，则修复回边界内」）—— 即**球拖到哪，面板就从哪长出**：

1. `panelPosFromBall()` 由球的位置反推面板位置（关闭键中心对齐球心）；
2. 若反推出来的面板越出视口 ⇒ `clampToViewport()` 把它钳回视口内（留 `VIEWPORT_MARGIN` 8px）；
3. **再让球跟进** `ballPosFromPanel()` 到钳制后的关闭键位置 ——
   于是「球与关闭键同坐标」这条不变量在任何拖动历史、任何视口尺寸下都成立，
   代价是球的落点可能被边界拉回（比两者错位、收起时球又跳走要好）；
4. **不落盘**：球的位置本就是会话内的临时落点，写 `ui:panel-pos` 等于把一次临时拖动
   升级成永久记忆。要持久化就拖**面板头部**，那条路径照旧写 `ui:panel-pos`。

- 球**不落盘**：拖动球只在本次会话内有效（`makeDraggable` 的写回调只改内存
  `ballPos`，参数名因此叫 `applyPos`）。要换球的位置就拖**面板本身**，
  面板位置 `ui:panel-pos` 仍旧持久。
- ⚠️ 旧实现把球的写回调挂在拖动过程的**每一帧**（`onMove`）上：任何一次
  pointerdown + 1px 抖动都会立刻 `write(BALL_POS_KEY)`；而 `setCollapsed` 的对齐
  只在 `readPos(BALL_POS_KEY) === null` 时发生 ⇒ **只要历史上碰过球一次，
  此后永远不再对齐关闭键**（用户报的就是这个）。
- 由此得到的交互语义：「点折叠 → 球落在关闭键原地 → 把球拖到别处 → 点球展开 →
  面板从球那里长出（越界则面板与球一起被拉回视口）→ 点折叠 → 球回到新的关闭键位置」
  在任何拖动历史下都成立。

### 2.1.3 选课列表注入的约定【v0.16 新增：批 3 片 1】

|---|---|
| **只认这两个类名，其余站点节点一概不碰** | 这是唯一能安全缩小「搬错东西」风险的办法 |
| **抓手用「最长的类名」，不用第一个**【`elementKey()`】 | 站点 class 顺序与个数都不稳定：同类按钮实测有 `cv-btn cv-tag cv-delete-volunteer` 与 `... cv-block-hide` 两种写法，取第一个会得到 `cv-btn`（到处都在用的通用类，毫无辨识度） |
| **幂等判据是「位置对不对」，不是自定义属性** | 与注入判重同一套理由：站点重绘会把节点放回原位，属性也一起没。判据必须是**当前实际位置** |
| **星标的判据是「紧邻前一个兄弟是不是它」** | 写成「在 title 之前」会恒真（`title.before(img)` 之后仍为真），幂等判断就永远返回「已在位」⇒ 什么都不做 |
| **`h5` 重排只在顺序真的不对时才动 DOM** | 每轮 `MutationObserver` 回调都会引发新一轮 DOM 变动；不判断就改，会把站点和我们自己拖进**重排循环** |
| **站点重绘后的补摆位必须独立于注入**（扫描末尾 `syncRelocation()`） | `enhanceUnit()` 第一行是 `if (ownsBlock(unit)) return` —— 把摆位挂在里面，站点重绘后那个教学班因「块还在」**永不重新摆位**，用户看到「搬一次就失效」 |
| **`h5` 改成 flex 才装得下第三个标签** | `h5` 宽 216px 是硬约束：课名 136（`float:left`，不占文档流宽度）+ 已选 41 + 间隙 4 = 177，**只剩 35px 而退选按钮要 41px**。改 flex 后课名 `flex: 0 1 auto; min-width: 0` 按内容占位，三个标签 `flex: 0 0 auto` 不缩放 |
| **目标次序：星标 → 课名 → 已选 → 退选**（`H5_ORDER`） | 用户指定；且必须**重复执行稳定**（站点重绘一次顺序就抖一次是不能接受的）。未知元素一律排到最后并保持彼此相对次序 |
| 🚫 **退选的「一次点击触发多次」是站点自身缺陷，本项目不修复、也不接管** | 用户对照实验（禁用脚本）确认基线同样存在。⇒ 后续做批 4 执行引擎时**不得**假设「点一次退选 = 一条请求」 |

### 4.1 接口清单【v0.11：已落地到 `src/sites/bkxk/api.ts`】

**批 1 已把下面这张表全部编码进 `api.ts`，并有逐字节报文断言钉住（`tests/suites/bkxk-api.test.ts`）。**

**通用**

- 端点基路径 `/xsxkapp/sys/xsxkapp/`。
- **鉴权：页面 cookie + 请求头 `token` 缺一不可**（漏 `token` 时服务端报
  `value sent to redis cannot be null`）。cookie 由页面 fetch 自动携带（Q-AE），
  `token` 由 `headers(token)` 显式附加。
- **`timestamp` 不是所有端点都要**：`volunteer.do` / `capacity.do` / `programCourse.do` /
  `publicCourse.do` / `recommendedCourse.do` 都**没有** query；
  只有 `courseResult.do` / `deleteVolunteer.do` / `celebrityfamous.do` 等带。
  代码里默认**不加**，需要时显式 `o.timestamp = true`。
- 响应判别（`classify()`）：`code=1` 成功 / `code=2` 业务拒绝（`msg` 即原因）/
  `code=302` 或 msg 命中 `/登录|认证/` → 登录失效 / 其它 → **未识别（落档）**。
  已知坑：被限流时站点先返回 `code=0`「请求过快，请登录后再试」，
  `code=0` 不在映射表内，靠 msg 含「登录」落兜底分支。
- 会话取值（`session.ts`）：`sessionStorage.studentInfo`（`.code` 学号 +
  **`.electiveBatch.code` 批次码**）、`sessionStorage.currentCampus.code` 校区、
  `sessionStorage.token` 令牌。⚠️ 批次码**不是** `currentBatch`。

- **🔴 站点把卡片高度写死成 210px**（v0.18 由 v5 采样实测）：`.cv-course-card` 是一张

  `.cv-caption-text` / `.cv-caption-red`）⇒ 内容必然从卡片下沿漏出去。
  **这条同时解释了「压了间距屏幕却没变化」** —— 卡片总高由这个固定值决定，不跟内容变。

  采样证据：`local/capture/dom-v5.txt`（`.sztb-bkxk-block` 宽 212 = 容器宽 212，

- **卡片内容区要用 `> *` 清零上下 margin，不能逐个列举**（v0.18）：站点给 `.cv-info` 的
  每个子 div 都挂了 `margin-top: 4px`，而各卡子元素数量不同 —— 列举漏掉的那一层，
  就是「部分卡片还是溢出」的原因。我们自己那块也要显式写 `.cv-info > .sztb-bkxk-block { margin-top: 0 }`，
  否则会被站点那条通配规则按 (0,1,1) 的特异性压过我们 (0,1,0) 的 `margin`。
- **🔴 卡片栅格是 `float:left`，行高由该行最高的卡决定**（v0.20 由 v6/v7 采样实测）：
  `.cv-course-card` 实测 `display: block; float: left; width: 243.993px; margin: 8px`，
  父容器 `section` 是 `display: block`（**不是** flex/grid）⇒ 同一行 5 张卡里只要有一张高 20px，
  整行就被撑高 20px。这就是用户看到的「已选卡占掉两行卡片的位置」的真机制 ——
  **压这张卡自己的高度治不了本**，得让那张卡别变高。
  采样证据：`local/capture/dom-v6.txt`（已选卡 info 232 vs 未选卡 212，差 20px）、
  `local/capture/dom-v7.txt`（拆到节点级，见 §2.1.4）。
- **站点给退选按钮单开了一整行 `div.cv-caption-text`**（v0.20 实测）：该 div 的

  ⇒ 这就是「已选卡比未选卡高 20px」的唯一来源。站点**靠按钮自己的 `tcid` 属性**认按钮，
  **不是按 DOM 位置找** ⇒ 把按钮搬进 `h5` 不会点错课（动手的前提依据）。
- **`h5` 装不下第三个标签，必须改 flex**（v0.20 实测）：`h5` 宽 216px 是硬约束，
  `span.cv-info-title` 是 `float: left` 宽 136px（float **不占**文档流宽度，所以
  「136+41+4=181 ≤ 216」的算法是错的），已选标签 41px、`margin-left: 4px`，
  实测**剩余仅 39px 而退选按钮 41px** ⇒ 直接塞会折行，必须 `display: flex` 让课名按内容占位。
- 列表页 `.cv-head` 是 12 列（课程编号 / 总号 / 名称 / 教师 / 时间地点 / 课容量 /
  已选人数 / 类别 / 文理 / 学分 / 远程 / 操作），卡片页是 **9 列且没有「操作」列**。

  **加列不许写死宽度**：我们改成 flex + 新列吃剩余空间，且所有改站点布局的规则
  都带 `:has(> .sztb-bkxk-col)` 前置条件（只有我们真插了列才改，避免外溢到别的列表）。
- `courseDataList` 是**真实全局对象**（含 `tcList` / `teachingClassID` / `classCapacity` /
  `electiveBatchCode` / `campus` / `teachingPlace` / `teacherName`）⇒ 教学班 id 与余量
  都能**零请求**拿到。本轮只用 DOM（用户拍板：纯 DOM + session，零额外请求）。

#### 4.3.1 ⚠️ 取数铁律：列表类端点的响应是**顶层 `dataList`**，没有 `data` 外壳

三条独立证据（缺一不可，因为这条结论与旧仓库代码相反）：

1. 三份真实响应样本的顶层键都是 `totalCount / dataList / msg / code / timestamp`；
2. HAR 里 `programCourse` / `recommendedCourse` 的响应正文前缀就是
   `"text":"{\"totalCount\":7,\"dataList\":[{\"selected\":true,\"tcList\":[…`；
3. 全 HAR 检索 `"data":{"(dataList|totalCount)` —— **命中 0 次**。

⇒ **旧仓库 `courses.js` 的 `C.flatten = json.data.dataList` 永远拿到空数组**
（旧脚本的「类别监控」实际是坏的）。**反面**：单对象端点 `capacity.do`
的响应**确实是** `{"data":{…}}`（`mainClassCapacity` 实测出现在该响应里），
所以 `api.capacityRemain(cls.data)` 的写法是对的 —— **两种形态并存，必须按端点分别处理**。

新实现据此写死：`listFrom(json)` **只认顶层 `dataList`**（拿不到返回 `null`），
`flatten(json)` 拿不到就返回 `[]` **并落一条 warn 日志**（用户拍板：不让「拿不到」静默消失）。
测试里有一条回归钉子：把旧仓库写法 `{code:'1', data:{dataList:[…]}}` 喂进去，
必须 `listFrom → null`、`flatten → []`。

#### 4.3.2 字段口径（来自 33 个真实教学班的逐字段扫描）

| 字段 | 落在哪一级 | 实测要点 |
|---|---|---|
| `courseName` / `credit` / `typeName` | **只在课程级** | tc 行上**连键都没有**（源样本 49 个 tc 命中 0）⇒ 必须回退课程级 |
| `departmentName` / `courseNatureName` | 课程级有值；tc 上**存在但全 `null`** | `pick` 必须把 `null` 与**空串**都算缺失，否则 `null` 会盖掉课程级的真值 |
| `campus` | **两级都没有** | 归一化后只能是 `null` |
| `classCapacity` / `numberOfFirstVolunteer` / `isMooc` / `isFull` / `isConflict` / `teachingClassID` / `courseIndex` / `teacherName` / `teachingPlace` | **只在 tc 级** | 全部是**字符串** `"0"` / `"1"`，**不是布尔** |
| `isFavorite` | tc 级，但 **33/33 全 `null`** | ⇒ 归一化成 `boolean \| null`；**收藏只能靠列表页 DOM 的星标**判断 |

| `courseTotalNumber` | tc 级，只有部分行有 | `"19022100"` → 数字 19022100 |
| `credit`（扁平结构） | 行内自带 | `noArranged` 两行实测是 `"1"` 与 `"2"` —— **逐行核对，不要按印象统一** |

- 取值顺序固定 **先 tc 后课程**，且 `pick()` **把空串也算缺失**（同时保留 `0` 与 `false`）。
- 开关类字段统一走 `toFlag()`：`"1"/"true"/true/1` → `true`，`"0"/"false"/false/0` → `false`，
  **其余一律 `null`** —— 给不出结论时**不猜**（`isConflict=null` 不能被说成 `false`）。
- 余量 `remainOf(c) = classCapacity - numberOfFirstVolunteer`，任一缺失返回 **`null` 而不是 0**。
- **交叉验证**：`isFull === "1"` 与 `classCapacity - numberOfFirstVolunteer <= 0`
  在 **33/33 行完全一致**（0 处不一致）⇒ 已写成一条真实性断言。
- 结构分两种：有 `tcList` 数组 → 嵌套（一个课程多个教学班，**空数组返回 `[]`**）；
  没有 → **整行即一个教学班**（`publicCourse` / `noArranged` 等扁平列表）。

#### 4.3.3 冲突判定口径（`time.ts`）

- 时间串形如 `5-18周 星期二 3-4节 致理楼L1-707`，**两种空格风格都要兼容**：
  每条正则用 `\s*`，**不写死空格**（真实语料无空格，旧 HAR 里有）。
- **地点取法**：取「节次匹配之后的剩余串」，按**匹配下标切片**（不用 `indexOf` ——
  `13-14节` 这种双位数会被截错）。
- **解析不出就返回 `null` / 空数组，不抛异常、不猜**：
  `day` 为 `null`、或任一侧不可解析 ⇒ 一律判**不冲突**（**宁可漏报，不误报**）。
- 冲突 = 同一天 + 节次闭区间重叠 + **存在共同周**（逐周扫描，因此单双周能正确相容）。
- `buildWeekBitmap(from, to, parity, len)`：**下标 0 = 第 1 周**；长度可传，
  非正值回落 `DEFAULT_WEEK_BITMAP_LEN = 18`（**跟随站点：默认 18 周，长度不固定**，
  实测样本里有 11 / 18 / 20 位）。冲突判定**不依赖位图长度**；
  长度不等时 `bitmapsOverlap()` 按**短的**比。
- 只用于判定「**自定义课程带来的新冲突**」，**绝不覆盖站点自己算好的
  `isConflict` / `conflictDesc`**（红线只加不减）。
- `parsePlace` / `placesConflict` 是给自定义课程用的地点比对；
  **`list-model.placeFromTimeText` 保持原样不动**（用户拍板：本批不连带重构它）。

#### 4.4.1 响应接管：`src/sites/bkxk/hijack.ts`

**做什么**：不接管脚本自己发的请求，而是接管**站点自己**发出去的那些响应的**正文**，
在返回给页面之前往里追加自定义课程的痕迹 ——
两条路径：列表响应里给撞课的 tc 打冲突标记；课表响应里塞进自定义课程的条目。

| 项 | 值 |
|---|---|
| 端点识别 | `TIMETABLE_RE = /elective\/teachingTime\.do/i` → `'timetable'`；`LIST_RE = /elective\/(?:programCourse\|unProgramCourse\|publicCourse\|recommendedCourse\|queryCourse\|course\|minorCourse\|retakeCourse\|sportCourse)\.do/i` → `'list'`；都不是 → `null`（**teachingTime 先判**） |
| 开关 | `hijack-timetable`（**课表注入**，🟠，**默认开** —— v0.24 用户拍板）/ `hijack-list-conflict`（**列表冲突追加**，🟠，**默认开** —— 旧仓库曾顾虑「把大半个列表标成冲突会让人不敢选课」，用户知情后仍要求一并默认开；关掉立即恢复原样）；🟠 自 v0.24 起**按声明的 default 走**，用户显式关过一次就不会被顶回来（见 `common/core/settings.ts` 的 `isEnabled`） |
| 改写列表 | `tc.isConflict = '1'`、`tc.conflictDesc = 原有 + '；' + '自定义课程：名(地点)'`、`tc.szuCustomConflict = true` |
| 改写课表 | 追加与站点同构的行，`teachingClassID = 'szu-custom-<课程id>-<段序号>'`，`szuCustom: true`，末尾 `totalCount` 累加 |

**五条实现约定（改代码前先读）**：

1. **只加不减**（红线）：站点的 `isConflict` / `conflictDesc` **绝不被清除或覆盖**；
   我们只把 `'0'` 改 `'1'`、把描述串**追加**在后面。
2. **开关在每次响应时判，不在安装时判** —— 所以即使开关是关的也照装接管器，
   用户拨开关**不需要刷新页面**。
3. `transformResponse()` 返回 `null` 的语义 = **「不改这个响应」**（空正文 / JSON 解析失败 /
   非对象 / `code !== '1'` / 一处都没改 都返回 `null`）。
4. 挂 XHR 而不是挂 `fetch`（`fetch` 也挂，纯防御）：站点所有请求走
   `BH_UTILS.doAjax → jQuery $.ajax → XMLHttpRequest`，而**我们自己的请求走 `fetch`**
   （`core/http.ts` 会带 `init.__szuSkip = true`，接管器认这个标记放行）。
   ⚠️ 改名要两边同步。
5. `readystatechange` 监听在 **XHR 构造时**注册 ⇒ 一定先于 jQuery 的回调执行，
   所以站点读到的是已改写的正文。改写的办法是
   `Object.defineProperty(xhr, 'responseText', {configurable: true, get: () => next})`，
   `responseType === 'json'` 时还要换掉 `response` 的 getter。
   `Wrapped.prototype = Orig.prototype` 是为了保住 `instanceof`。
6. **【v0.24 新增，最重要的一条】必须装到页面 realm，不是沙箱的 `globalThis`。**
   本脚本 header 声明了 `@grant`（`GM_setValue` 等）⇒ Tampermonkey 把脚本放进**沙箱**
   执行，沙箱里的 `globalThis` **不是页面的 `window`**。把包装后的 `XMLHttpRequest`
   写在沙箱上，页面那份**一个字节都没动** ⇒ 站点请求照走原生 XHR ⇒ 接管**完全失效，
   而且没有任何报错**（这正是用户实测「开关勾了却没反应」的真因）。
   所以 `installXhr` / `installFetch` / `installHijack` 的默认目标一律走
   `pageRealm()` = `typeof unsafeWindow !== 'undefined' ? unsafeWindow : globalThis`；
   `target` 参数只留给档 1 测试塞假全局对象。
   ⚠️ 旧仓库（`C:\Project\szu_bkxk`）是 `@grant none`，直接跑在页面 realm，
   所以它当年这样写是**有效的** —— 迁移时漏掉了「本项目的运行环境已经变了」这一层。
   已加回归测试：把假环境挂到 `globalThis.unsafeWindow` 上，调**不带参数**的
   `installHijack()`，断言包装落在它身上。

**⚠️ 已知的宽松匹配（用户 2026-10 拍板：与旧仓库保持一致，故意不锚尾）**：
`/elective\/teachingTime\.do/i` 会把 `teachingTime.do.bak` 也认成课表端点。

#### 4.4.3 自绘课表：`src/sites/bkxk/timetable*.ts`

**形态（用户拍板：照旧仓库）**：**不**自建容器、**不**重画整张表、**不**放进悬浮窗 ——
而是在站点每一列里按「星期 + 起止节次」算出 `top` / `height`，追加一个 `.cv-lesson`，
内部放与站点同构的 `.cv-course-card-single`（带我们的标记类以示区分）。

**站点 DOM 契约**（来自旧仓库 `docs/curriculum.do.html`；选择器集中在
`timetable-model.ts`，改结构只改那一处）：

```
#myCourseTable
  .cv-my-course
    .cv-col.cv-left                      ← 左侧「节次」列
      .cv-lesson > div[style=height]     ← 14 个节次刻度（实测单节 54px）
    .cv-col.cv-right                     ← 每天一列（周一…周七）
      .cv-head                           ← 「周一」
      .cv-lesson[start][end][style=top]  ← 一节课的容器
        .cv-course-card-single > div > div{课程名, 时间, 地点, 教师}
```

**几何**：`top = 28 + (起始节次 - 1) × 单节高度`；`height = 节数 × 单节高度 + 1`
（`+1` 是旧仓库的实测值，贴边线用）。单节高度**运行时从左侧真实刻度量**
（`pickSlotH`，量不到才退回 54），表头高度固定用 28。

**读站点卡片的口径（沿用旧仓库）**：课名 = 卡片里**第一个非空文本**；
时间 = **第一个长得像 `\d+-\d+周` 的文本**；**读不到时间的卡片直接丢**（判冲突必须有时间）；
我们注入的卡片按标记类**整词**跳过。
⚠️ **整词判定**：旧仓库用 `indexOf('szu-tt-card')`，子串匹配会误判 ——
本项目用 `hasClassToken()`（按空白切分后 `includes`），已用测试钉住。

**冲突是「整门课一个布尔」**（旧仓库口径）：这门课的地点与**任一条**已选课程冲突，
则它的**所有**节次都标冲突。

**⚠️ 本项目新增的 `writing` 闸门**：我们自己的 `appendChild` 也会触发
`MutationObserver`，不设防就会「注入 → 触发回调 → 清掉再注入」无限循环。
写 DOM 期间置 `writing.busy`，回调看到它就跳过。
【v0.23】这个闸门对象**提到模块级**，并被 `refreshTimetable()` 复用（见 §4.5.4）。

**⚠️【v0.26 修正】光有同步闸门不够 —— 真正的判据是「我们的节点还在不在」**：
`MutationObserver` 的回调是**异步**投递的（当前任务结束后的微任务里才跑），
而我们写 DOM 是同步的：`render()` 结束时 `writing.busy` 已经复位，回调随后才跑
⇒ 闸门**拦不住自触发**。手测现象：日志每 300ms 刷一条
`课表注入自定义课程段 6 个（已选课程 14 门）`，同时白白清掉再重建一遍 DOM。
现在 `schedule()` 里加一条纯函数判据 `needsRescan(countInjected(table), 启用课程数)`
（= `启用课程数 > 0 && 我们注入的节点数 === 0`）：**只有站点重绘把我们抹掉了才重画**，
节点还在就什么都别做（这正是旧仓库 `timetable.js` 的写法）。
`refreshTimetable()` 不受这条判据限制 —— 用户改完课程必须无条件重画。

**⚠️【v0.26 修正】卡片的三行文字必须包在中间那层 `div` 里**：
站点结构是 `.cv-course-card-single > div > div{课程名, 时间, 地点, 教师}`，
**中间那层不是装饰** —— 站点给卡片**本身**的 CSS 会把它的**直接子元素**排成一行。
v0.26 前我们漏了这层，手测现象：「一节课左边显示课程名，中间显示时间，右边显示地点，
预期应该是上中下的排列」。现在 `buildCard()` 先造 `div.sztb-bkxk-tt-lines` 装那几行，
`TT_CSS` 里再对我们自己的类名显式 `display: block`（仍然只动我们的节点、不吃 `!important`）。

**⚠️【v0.28 新增】接管可能「根本没赶上」—— 先诊断，再补偿**（分支 `feat/bkxk-tt-late-render`）

**为什么有这一节**：用户第十轮手测问「关闭【自绘课表】后，站点自己的绘制逻辑不该把自定义课程画出来吗，现在没有」。
查 HAR（`local/capture/课表页1.har`）得到两条硬事实：
① 课表**确实**走 `POST elective/teachingTime.do` —— 渲染路径在 `curriculum.min.js` 里，
`queryStudentTeachingTime({studentCode}).done(...)` 拿 `e.dataList`，拼
`{ sectionList: { morringSectionList, afternoonSectionList, nightSectionList }, teachingTime }`
交给 `CVMyCourseTable.init($("#myCourseTable"), r)` 绘制
（⚠️ **站点把 `morningSectionList` 拼成了 `morringSectionList`**，我们得照着它拼；
`init` 的第一个参数是 **jQuery 对象**，内部会调 `.html()` / `.outerHeight()` / `.attr()`）；
② 站点**拿到 14 条并画出来了**，而我们那一版响应**没有被改写**（【日志】里没有 `[接管] timetable` 行）。
⇒ `augmentTimetable` 生成的行与站点期望**同构**，问题不在数据，在**时机**。

**病因：用户脚本的注入是异步的，页面可能先跑完。**
用户实测的判据很干净 —— **硬刷新（或 F12 限速 3G）总能注入，普通刷新（F5）不能**，
且成功时必有 `[接管]` 日志、失败时必无；资源计时印证：暖缓存下站点
`curriculum.min.js @45ms` / `teachingTime.do @75ms`，而 Tampermonkey 投脚本、我们装上接管约在
**200ms 之后**；硬刷新/限速时站点反而慢（`@39ms` / `@285ms`）⇒ 我们就赶上了。
**包装只作用于「之后新构造」的实例**，那一发原生 XHR 完全静默（`@run-at document-start` 已是最早时机，
再往前没有位置可站）⇒ 只能**事后补偿**，不能靠「装得更早」。

**① 诊断（选项 1，两个模块）**
- `page-realm.ts`（新文件，从 `hijack.ts` 抽出）：`pageRealm()` / `pageRecord()` —— 拿页面 realm 的对象，
  用于读 `performance` / `jQuery` / `CVMyCourseTable`。
- `hijack.ts`：模块级记 `installedAtMs = performance.now()`，安装日志变成
  `响应接管已安装（XHR=true fetch=true，装上时刻 218ms）`；新增
  `explainTransform(kind, text, items): { reason, text, changed }` 与 `SKIP_TEXT`（`SkipReason`：
  `rewritten` / `empty-text` / `no-courses` / `bad-json` / `not-object` / `bad-code` / `nothing-changed`），
  `transformCurrentResponse` 对每一条早退路径落一行
  `[接管] <kind> 响应没改：<人话原因>`（**`no-courses` 与 `empty-text` 不打**：没有自定义课程是常态，
  否则列表页每次请求都刷一行）；开关关着时**刻意不打任何日志**（那是用户的选择）。
- `timetable-late.ts`：`readTeachingTimeStarts()` 从 `performance.getEntriesByType('resource')` 里
  挑 `teachingTime.do` 的 `startTime`，`judgeLate(installedAtMs, starts)` 给出判词，例如
  `站点在 75ms 就请求了 teachingTime.do，我们到 218ms 才装上接管 ⇒ 晚了 143ms（那一发是原生 XHR，我们改不到）`；
  **查不到资源计时就只说「查不到」，不硬判「没晚」**。进课表页时打一次。

**② 晚到补偿（选项 2）：站点已经画完、里面却没有我们的课 ⇒ 自己补一次**
- **触发位置**：`scan()` 里拿到表之后、**在自绘开关判断之前** —— 用户要的正是「关掉自绘也让站点自己画」。
- **触发判据**：纯函数 `shouldOwnRender({ hijackOn, selfDrawOff, alreadyTried, enabledCourses, missingCourses, siteCards })`
  **六条全真**：接管开着、自绘关着、本次页面还没补过、有启用的课程、站点已画的卡片里**一门我们的都没有**、
  站点自己画了至少一张卡片。**刻意不看时钟**（判据全是页面既成事实）。
  `selfDrawOff` 的必要性：自绘开着时我们本来就会立刻画上，那时再补一次等于每次刷新白跑一个请求 + 白重画整张表。
- **动作**：`fetchMergedTimetable()` 用 `bkxkSend` 打一次 `teachingTime.do`（`POST`、带 `token`、
  `timestamp: true`），把响应交给 `augmentTimetable` 合并自定义课程，再调站点自己的
  `CVMyCourseTable.init($('#myCourseTable'), { sectionList, teachingTime })` 重画整张表。
  读不到 `sessionStorage.sysParam` 的节次表就落 warn 跳过（**仍由自绘兜底**）；
  任何失败（非 200 / 非 JSON / `code≠1` / 没有 `dataList` / 一段都合并不进去）都**只落日志不抛错**。
- **一次性**：`ownRender.tried` 每页只补一次 —— 补完会触发站点重绘、进而触发我们的观察器，
  没有这个闸门就会「补 → 观察器 → 再补」。
- **配套去重**：站点画出来的卡片在 `readExistingCards()` 里是**看得见**的（只跳过带我们标记类的），
  于是 `renderedCourseNames(cards)` + `planInjection()` 里 `if (rendered.has(course.name.trim())) continue;`
  —— **站点画过的课，自绘不再画第二份**。两条路互补而不是叠加。

**只在课表页生效**：`startTimetableInjection()` 自己判 `location.pathname.includes('curriculum.do')`
（适配器 `pages` 里有同源判据，这里再挡一次是为了让测试与「误注入」都无路可走）；
等容器最多 20 × 500ms，超时落 warn 放弃；观察站点重绘 300ms 去抖后补注入。

**门槛/开关**：`timetable-self-draw`（🟢 默认开）；关掉时**不是不注入，而是会把已注入的节点清掉**。

### 4.5 自定义课程标签页与结构化表单【v0.23 新增】

**为什么提前**：批 3 其余（`hijack` / `timetable`）做完后，写本轮手测清单时发现一个硬缺口 ——
**全项目没有任何写入自定义课程的入口**（数据层当时是只读的），于是「响应接管」与「自绘课表」
**根本无法手测**：没有数据就没有东西可注入。
另外需求文档 **Q-F** 早就定过「把『添加自定义课程』做成 UI 版，**不纯靠文本识别**」，
只是排在阶段 5。用户拍板把这一页**提前**到批 3 之后做（`ask_user_question` 选 D）。

#### 4.5.1 结构化表单：不让用户手写时间串

- **形态**：课程名（必填）+ 教师（可空）+ **若干段上课时间**，每段 = 周次起止 + 单/双周下拉 +
  星期下拉 + 节次起止 + 地点（必填）。【再加一段】最多 8 段。
- **为什么否掉旧仓库的「一个文本框」**（`ui.js:441-540` 只有一个「时间地点」输入框，
  靠 `NS.time.parse` 识别，认不出就 toast 拒收）：那正是 Q-F 要淘汰的做法 ——
  用户得记住 `5-18周(单) 星期二 3-4节 致理楼L1-707` 这种格式，写错只得到一句「时间未解析」。
- **纯逻辑与界面分离**：`custom-form.ts`（无 DOM，可档 1 测试）负责草稿 → `place` 文本、
  校验、回填；`tabs/custom.ts` 只做 DOM 与事件。**校验失败返回的是给用户看的中文短句**
  （`周次要填 1-52 之间的整数` / `周次起止颠倒：起始周不能大于结束周` / `请选择星期几` …），
  界面直接显示，不另写一份文案。

#### 4.5.2 `place` 文本仍是唯一真源

- 表单状态（`SegmentDraft`，数字**一律字符串**，与 `<input>` 一致）在提交时拼成 `place` 文本
  （`placeFromDraft` → `segToPlaceText` / `placeTextFor`），**`segs` 依然不落盘** ——
  与 §4.4.2 一致，好处是解析口径日后改了，历史数据自动跟着变，不用做数据迁移。
- **生成与解析必须互为逆运算**：`segToPlaceText` 的输出再喂给 `time.ts` 的 `parseSegment`，
  五个字段（周次/单双周/星期/节次/地点）必须完全一致。这条已被测试用**真实语料**钉住：
  `tests/fixtures/bkxk-teaching-place.json` 的 **49 条去重地点全部能解析、合计 66 段**，
  逐条做 `place → 表单 → place → 再解析` 的往返比较。
- **提交前自检**：界面在写盘前再算一次 `parsePlace(place).length === segs.length`，
  不等就**拒收**并落 `log.warn` —— 防止「生成口径」与「解析口径」将来各改一半而静默出错。

#### 4.5.3 界面动作与「编辑回填」

- 列表每项：色条（`colorAt` 按门数轮转）+ 启用勾选框 + 课名 + `教师 ｜ 时间地点` +
  「解析出 N 段」（解析不出来显示红字提示）+【修改】【删除】；底部【清空全部】。
- **【修改】是本项目比旧仓库多出来的能力**（旧仓库只能增/删/启停）。回填走
  `draftsFromText(course.place)`；**解析不出来时**（历史数据写得很野）不静默：
  回填一段默认值 + `toast(…, 'warn')` + `log.warn`，让用户重填。
- 删除单条**不**二次确认（可再添加）；【清空全部】走 `ctx.host.confirm`（`danger: true`）。
- 改动**立即写盘**，没有「保存」按钮 —— 与旧仓库一致。
- **点【修改】与【取消编辑】后自动把视图滚回表单标题**（v0.25）：
  `scrollToForm()` = `formTitle.scrollIntoView({ block: 'start' })`。
  ⚠️ 这里原本写的是 `root.scrollTop = 0`，而 `root` 是**标签页自己的容器**、
  真正滚动的是外层 `.sztb-body`（`overflow: auto`）⇒ 那是一个**静默的空操作**：
  不报错、也不起作用，用户点了【修改】还停在下半屏的列表位置。
  用 `scrollIntoView` 是因为它会自己找最近的可滚动祖先，将来面板结构变了不用跟着改。
  不聚焦输入框（用户可能只想改地点/时间）、不带动画（面板小、距离短，动画像卡了一下）。

#### 4.5.4 `mutate()` 是唯一写入出口，并且每次改完都要 `refreshTimetable()`

- 所有增删改都过 `mutate(next)`：`courses = next` → `writeCustomCourses(next)` →
  重画列表与冲突提示 → **`refreshTimetable()`**。
- **为什么必须主动重画**：增删课程只改 storage，**站点 DOM 一个字节都没动** ⇒
  课表页的 `MutationObserver` 不会触发，用户会以为「加了课却没出现」。
  旧仓库在每处改完都调一次 `NS.timetable.render()`，同一个原因。
- `refreshTimetable()` = `scan(writing)`，**不在课表页（找不到表）时静默返回 0**，
  所以调用方不需要自己判页面；它与观察器**共用同一个闸门对象**，否则会打架。

#### 4.5.5 总开关 `custom-courses` 的闸门只放一处

- 🟢 `custom-courses`（默认开）此前**没有任何代码读它**（一个空开关）。v0.23 接上：
  **闸门放在 `src/sites/bkxk/custom.ts` 的 `readEnabledCustomCourses()` 开头** ——
  它是 `hijack` 与 `timetable` 读自定义课程的**唯一入口**，关掉时返回空数组，
  于是「不参与冲突判定」与「不往课表注入」自动同时成立，不必在两处各写一遍。
- 标签页本身也认这个开关：关掉时**整页禁用**（表单与列表收起来，只留一句说明），
  且每次写数据前再 `guard()` 一次（防止页面开着时用户在设置页把它关掉）。

#### 4.5.6 仍未接的开关（记在账上）

`list-extra-columns`（🟢 默认开）**同样至今没有任何代码读它** ——
它对应的「列表额外列」功能还没做（不属本轮）。**看到它别以为是坏了**，
接它的时候请照 §4.5.5 的思路找「唯一入口」，不要在每个消费点各判一次。

## 5. 抓包工作流（本项目标准动作）

1. 用户开 mitmweb（`--listen-port 8080 --web-port 8081`），
   Edge 用 ZeroOmega 切到 mitm 情景模式（**只代理目标站点**）。
2. 用户操作目标站点，抓完把 `.flow` 存到 `local/capture/`。
3. 跑 `tools/flow_probe.py` 确认可读 → `tools/flow_index.py` 出请求总表 →
   **与用户确认哪些请求是目标接口**。
4. `tools/flow_slice.py` 分片（每片约 24KB）→ **本地模型**提炼 →
   汇总写进本文（或 `docs/接口清单.md`）。
5. 基于清单写油猴脚本；**主 agent 只读清单，不读原始抓包**。
6. 提醒用户：抓完立刻把 ZeroOmega 切回「直接连接」并停掉 mitmweb。

> ⚠️ `local/capture/` 里的 `.flow` 可能含真实姓名 / 学号 / 手机号，
> **绝不喂云端模型**，只走本地 LM Studio。

## 6. Git 分支策略【v0.3 新增】

用户授权：「适当时候你需要自己创建合适 git 分支，或合并 git 分支」。

| 场景 | 分支 | 说明 |
|---|---|---|
| 文档维护 | **直接在 `master`** | 文档是项目的活记录，不属「新功能」 |
| 框架骨架 | `feat/framework-skeleton` | 阶段 1，合并前需用户确认 |
| core 细节 | `feat/core-<模块>` | 如 `feat/core-http`、`feat/core-storage` |
| 悬浮窗 | `feat/ui-panel` | 阶段 1 |
| bkxk 重构 | `refactor/bkxk-into-framework` | 阶段 2，**大改动，必须独立分支** |
| UOOC 旧版 | `feat/uooc-legacy` | **先做**（Q-V 定稿：旧版有参考脚本可依） |
| UOOC 新版 | `feat/uooc-new` | 后做，需先解决 V7/V8 |
| 发布 | 从 `master` 打 tag `v0.x.y` | 与 `package.json` 的 `version` 一致 |

**约定**：

- 默认分支 `master`（Q-P 定稿）。
- 任何修改都要 commit，不攒批。
- commit 前先 `git status` 确认改动范围。
- 出现冲突 / 意外回退 / 分支错乱 ⇒ **立即上报**，不自行处理。
- 合并回 `master` 前告知用户。

> 🚫 **站点自身缺陷（已标记，本项目不修复）——「一次点击触发多次退选」**
>
> **现象**（用户 m02124）：「当前页面上展开卡片内有几个退选按钮就会被触发几次（严重bug）」。
> **定性**（用户 m02126）：「检查了，**不装我们脚本时也可能会出现这种问题**，那么这个标记一下，
> 不作为脚本 bug，不修复。」
>
> 排查过程与可复用结论：退选按钮的**点击处理是站点自己的**，我们把节点搬进 `h5`
> **只改变位置、不复制节点**，因此**结构上不可能**把一次点击变成多次；站点在卡片重绘后
> 若**追加**（而非替换）事件绑定，历史绑定就会累积 —— 这解释了「有几个按钮就触发几次」。
> 用户用**禁用脚本的对照实验**确认了基线同样存在该现象，据此排除本项目。
>
> ⚠️ **对后续开发的影响**：`sztb` 只**注入**、不接管退选的点击；将来做批 4 的执行引擎时，
> **不得**假设「点一次退选 = 一条请求」。若日后要在监控里统计退选结果，需按
> 实际返回而不是按点击次数计数。

> 1. 注释里不要出现带 `*/` 的 glob（如 `src/**/*.ts`），会提前闭合块注释。
> 2. Node 24 的类型擦除是 **strip-only**，全项目**禁止 TS 构造函数参数属性**

>     要改的那条 XHR；**包装只对「之后新构造」的实例生效**，那发原生请求**完全静默**。
>     ⚠️ 遇到「有时生效、有时不生效」先想**谁快谁慢**，别急着怀疑开关或 realm ——
>     本次的决定性线索是用户发现的：**硬刷新（或 F12 限速 3G）反而一定能注入**（站点变慢了）。
>     ⇒ 凡要接管页面自己发起的请求，都要**额外准备一条事后补偿路径**，并且把「装上时刻」
>     与「站点请求时刻」都打进日志（`performance.now()` + `performance.getEntriesByType('resource')`）。

>     调站点渲染器重画）会再次触发站点重绘 ⇒ 我们的 `MutationObserver` 又会跑一遍 `scan()`
>     ⇒ 没有 `ownRender.tried` 这种一次性标记就是新的死循环；而补偿让**站点**把我们的课画出来之后，
>     自绘那条路必须能认出来并**跳过**（`renderedCourseNames()` 按课名比对），

## 9. 换行符与 `.gitattributes`（v0.7 新增）

本机 git 配置 `core.autocrlf=true`，仓库原先没有 `.gitattributes`，导致：

- `src/userscript-header.txt` 在 checkout 时被转成 CRLF ⇒ 产物**首行**变成
  `"// ==UserScript==\r"`（18 字符，多一个 CR）⇒ `tools/verify-build.mjs`
  的「首行是 ==UserScript==」自检**误报失败**。
  Tampermonkey 能容忍 CRLF 头，所以真实环境一直没暴露，**只有自检工具被骗**。
- 每次 commit 刷一屏 `LF will be replaced by CRLF` 警告。

**修法（两层，缺一不可）**：

1. `.gitattributes` 强制 LF：`* text=auto eol=lf`；
   `*.cmd` / `*.bat` 保留 CRLF；`png/jpg/ico/exe/flow/har/woff/woff2` 标 `binary`
   （抓包 `.flow`、样本 `.har` 是二进制混合格式，绝不能让它做换行转换）。
2. `build.mjs` 里再兜一层：读头模板与 bundle 后统一 `\r\n?` → `\n`。
   **构建不该依赖使用者的 git 配置** —— `.gitattributes` 只对遵守它的 checkout 生效。

### 已执行：改写 git history 的作者（v0.8 完成）

**结论：早期 `dsh` commit 的作者已全部改写为 `emo_bird <f12y34m56@163.com>`。**

起因：最初 8 个文档 commit 的作者是 `dsh <dsh@local>`（当时用 `-c user.name=dsh` 写的，
**实际是 8 个，不是更早记录的 5 个**）。用户要求统一为 `emo_bird <f12y34m56@163.com>`。

**执行过程**：

1. 首次尝试（会话 2，**受限沙箱**）：
   - `git rebase --root --exec '…'` ❌ —— `--exec` 要 spawn MSYS `sh.exe`，
     报 `sh.exe: *** fatal error - couldn't create signal pipe, Win32 error 5`；
   - `git filter-branch --env-filter '…'` ❌ —— 同样要 spawn `sh.exe`，同一条报错，exit 66。
   - ⇒ 与堵死 esbuild JS API 的是**同一堵墙**（DSH 沙箱禁命名管道）。
2. 用户切到 `danger-full-access` 后：
   - 实测 `"C:\Program Files\Git\bin\sh.exe" -c "echo sh-works-from-git"` ✅ exit 0
     ⇒ **命名管道限制消失**，`filter-branch` 恢复可用。
   - 先在**临时分支**上试跑，核对无误后才动真分支。

**最终采用的操作（可复现）**：

```sh
git branch tmp-rewrite-trial feat/framework-skeleton          # 临时分支，从未切换过去
FILTER_BRANCH_SQUELCH_WARNING=1
git filter-branch -f --env-filter '
if [ "$GIT_AUTHOR_NAME" = "dsh" ]; then
  export GIT_AUTHOR_NAME="emo_bird"
  export GIT_AUTHOR_EMAIL="f12y34m56@163.com"
  export GIT_COMMITTER_NAME="emo_bird"
  export GIT_COMMITTER_EMAIL="f12y34m56@163.com"
fi
' -- tmp-rewrite-trial                                          # 注意：只跟一个 ref，不是 --all
# 核对通过后：
git branch -f feat/framework-skeleton fb476ef
git branch -f master 43341d5
git checkout feat/framework-skeleton
git update-ref -d refs/original/refs/heads/tmp-rewrite-trial  # 删残留备份 ref
```

**⚠️ 关键发现：`filter-branch` 连 root commit 的 hash 一起改了**

`dade49f` 的 author / committer / date **元数据一字未改**，但 hash 变成 `4495e3a`。
原因：`filter-branch` 会重写 `--` 之后的**整条链**，root 即使内容不变也会被
`commit-tree` 重新生成，不会原样复用。**后果是 root hash 变化 ⇒ 与远端
`origin/master`（仍指向 `dade49f`）成为两条不相干的根。**

**hash 对照与校验结果**：

| 旧 | 新 | tree | 说明 |
|---|---|---|---|
| `dade49f` | `4495e3a` | `b3a0727f…` 相同 | Initial commit（GitHub 服务端生成） |
| `8d033f0` | `43341d5` | `c35474de…` 相同 | 旧 master tip，新 master tip |
| `a7d9e2c` | `fb476ef` | `e9f2d206…` 相同 | 旧 feat tip，新 feat tip |

- 全部 22 个 commit 的 **tree 哈希逐一比对相同**（内容逐字节未变）；
- **提交日期、提交信息、提交顺序（线性）全部保留**；
- 作者统计：`emo_bird <f12y34m56@163.com>` × 21 + GitHub noreply × 1，**`dsh` 归零**；
- `master` 仍是 `feat` 的祖先（两线统一）。

**⚠️ 推送注意**：`master` 与远端根不同 ⇒ **必须 force-push**
（建议 `git push --force-with-lease origin master`）；
`feat/framework-skeleton` 从未推送过，`git push -u origin feat/framework-skeleton` 不需要 force。
**截至 v0.8 尚未推送。**

**⚠️ pwsh 陷阱（本次新增）**：`git rev-parse '8d033f0^{tree}'` 的 `^{tree}` 若**不加引号**，
会被 pwsh 当作**花括号展开**吃掉，报
`fatal: ambiguous argument 'dAByAGUAZQA=': unknown revision`
（那是被拆碎的 base64 片段）。**涉及 `^{…}` 的 rev-parse 一律加单引号。**
