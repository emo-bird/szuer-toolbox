## 3. 总体架构（用户已确认 Q4 = C）

**「框架 + 适配层」**：统一悬浮窗 UI，每个站点往里面接入模块。

```
┌─────────────────────────────────────────────┐
│  悬浮窗（唯一控制面板）                        │
│  ┌───────────────────────────────────────┐  │
│  │ 标签页：全局设置 / 日志 / 登录态 / 功能列表 │  │
│  │  + 各站点注册的自有标签页（可多个）        │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
              ▲ 注册
┌─────────────┴───────────────┐
│  站点适配层 (sites/*)         │
│  bkxk/  uooc/  ehall/  ...   │
└─────────────┬───────────────┘
              ▼ 依赖
┌─────────────────────────────┐
│  框架核心 (core/*)            │
│  bus 事件总线 / storage 存储   │
│  log 日志 / http 请求出口+限流 │
│  settings 全局设置 / llm 客户端│
└─────────────────────────────┘
```

**核心原则（拟定，待确认）**：

- 站点适配层**只依赖 core**，站点之间**零耦合**；跨站点数据一律经 core 的通用存储。
- 每个站点是一个 `SiteAdapter`，声明：`id` / `name` / `match`（匹配哪些 URL）/
  `tabs[]`（注册哪些标签页）/ `init()`。
- 悬浮窗本身不知道任何站点的业务，只认 adapter 注册的接口。

## 8. 安全与风控红线（**最高优先级**）

用户 m00023 明确：「**风控类接口，修改不可逆类接口要在设置面板中复选框启用才真有效**」。

### 8.1 本项目红线（拟定，继承 szu_bkxk R1–R5）

| # | 红线 | 落点 |
|---|---|---|
| N1 | **风险开关默认关闭，且必须经设置面板复选框启用才真生效** | `core/settings` + Bonsai `confirm-dialog` 二次确认 |
| N2 | **请求限流硬下限 200ms**（沿用 R2），所有目标站点请求走同一串行队列 | `core/http` |
| N3 | **凭证不落盘**（沿用 R3）：token / cookie / 学号只在内存，日志脱敏 | `core/log` + `core/http` |
| N4 | **未识别响应全量落档**（沿用 R4） | `core/http` |
| N5 | **不自动启动高风险任务**（沿用 R5）：抢课、监控、自动答题一律手动点开始 | 各 adapter |
| N6 | **不做自动化测试的风险接口**：改由用户手测，AI 只提供固定格式清单 | 测试策略 |

### 8.2 风险分级（拟定，待用户确认）

| 级别 | 例子 | 门禁 |
|---|---|---|
| 🔴 不可逆 | 提交选课 / 提交测验答案 / 交卷 | 默认关 + 复选框 + 二次确认 |
| 🟠 留痕 | 拉取测验答案 / 心跳上报 | 默认关 + 复选框 |
| 🟢 只读 | 查容量 / 查课表 / 读页面数据 | 可直接用 |

### 8.3 需向用户明示的风险（**不是劝阻，是尽责提示**）

- **U6–U9（测验答案读取/导出/自动作答）** 属于典型「刷课」行为，
  UOOC 侧可能判定为异常作答并**处理账号（成绩作废 / 封禁）**。
  依红线 N1/N5，这些功能一律默认关闭、复选框启用、不进自动化测试。
- **U5 多窗口**若指同一账号并发播放，可能直接被判定异常。
- 原仓库免责声明口径可直接继承：
  > 本项目仅供技术学习研究，**不得用于任何违反校规或法律的用途**。
