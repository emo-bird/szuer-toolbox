## 3. 总体架构【确认】框架 + 适配层

```
┌─────────────────────────────────────────────┐
│  悬浮窗（唯一控制面板）                        │
│  基础标签页：全局设置 / 日志 / 登录态 / 功能列表 │
│  + 各站点注册的自有标签页（可多个）             │
└─────────────────────────────────────────────┘
              ▲ 注册
┌─────────────┴───────────────┐
│  站点适配层 (sites/*)         │
│  bkxk/  uooc/  …             │
└─────────────┬───────────────┘
              ▼ 依赖
┌─────────────────────────────┐
│  框架核心 (core/*)            │
│  bus / storage / log / http   │
│  settings / llm               │
└─────────────────────────────┘
```

**核心原则【拟定】**：

- 站点适配层**只依赖 core**，站点之间**零耦合**；跨站点数据一律经 core 通用存储。
- 每个站点是一个 `SiteAdapter`，声明：`id` / `name` / `match[]` / `tabs[]` / `init()`。
- 悬浮窗不认识任何站点业务，只认 adapter 注册的接口。

## 6. 登录态与凭证【确认】

**策略**：直接劫持页面已有登录态，**不做接口登录、不处理验证码**。
每个站点账号系统不同 ⇒ 每个 adapter **自己实现取态逻辑**。

| 站点 | 载体 | 已知信息 |

同浏览器并存两个 UOOC 账号需要切 cookie，可能互相覆盖。
⇒ U6 开发时需先确认「刷答案账号」与「用答案账号」是否分浏览器/分 profile 操作。

## 8. 安全与风控红线

用户在 Q8 明确：**「风控类接口，修改不可逆类接口要在设置面板中复选框启用才真有效」**。

### 8.1 本项目红线

| # | 红线 | 落点 |
|---|---|---|
| N1 | **风险开关默认关闭，且必须经设置面板复选框启用才真生效** | `core/settings` + Bonsai `confirm-dialog` 二次确认 |
| N2 | **请求限流硬下限 200ms**（继承 R2），所有目标站点请求走同一串行队列 | `core/http` |
| N3 | **凭证不落盘**（继承 R3）：token / cookie / 学号只在内存，日志脱敏 | `core/log` + `core/http` |
| N4 | **未识别响应全量落档**（继承 R4） | `core/http` |
| N5 | **不自动启动高风险任务**（继承 R5）：抢课、监控、自动答题一律手动点开始 | 各 adapter |
| N6 | **风险接口不做自动化测试**，只由用户手测 | §12 |

### 8.2 风险分级【拟定，用户已认可「做的正确」】

| 级别 | 例子 | 门禁 |
|---|---|---|
| 🔴 不可逆 | 提交选课 / 提交测验答案 / 交卷 | 默认关 + 复选框 + 二次确认 |
| 🟠 留痕 | 拉取测验答案 / 心跳上报 / 自动连播 | 默认关 + 复选框 |
| 🟢 只读 | 查容量 / 查课表 / 读页面数据 / 倍速静音 | 可直接用 |

> 按此分级，**U6 / U7 / U8 / U9 全部归 🔴 不可逆级**（默认关 + 复选框 + 二次确认 + 不进自动化测试）。

## 9. 请求出口与数据落地

### 9.1 请求出口【确认】

**使用 `GM_xmlhttpRequest`**（而非页面 `fetch`）⇒ 需要 `@grant GM_xmlhttpRequest`。

**拟定影响**：

- `core/http` 基于 `GM_xmlhttpRequest` 封装，天然绕过页面同源限制。
- 限流队列（N2）放在 `core/http` 的出口层，所有站点共用。
- **需注意**：`GM_xmlhttpRequest` 默认不带页面 cookie，
  而 `szu_bkxk` 的写接口依赖请求头里的 `token`（不是 cookie），
  但 UOOC 的登录态形态**待抓包确认** —— 若 UOOC 依赖 cookie，
  则需显式传 `Cookie` 头。**这是开工前必须验证的点（Q-M）。**

### 9.2 数据落地【确认】

| 数据 | 形态 | 位置 |
|---|---|---|
| 抓包原始数据 | mitmproxy `.flow` / HAR | `local/capture/`（**不随 git**） |
| 测验答案 | **JSON 文件**，手动导出/导入 | 导出的落 `local/export/`；站内共享经 `GM_setValue` |
| 自定义课程 | 跨站点通用存储 | `GM_setValue` |
| 全局设置 / LLM 配置 | 跨站点通用存储 | `GM_setValue` |
