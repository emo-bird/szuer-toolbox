# A. 自动连播（U3）

## A.1 总原则

连播开启后，**按目录顺序往下执行**。走到每一项时，按其**资源类型**决定动作，
动作完成后进入下一项。

## A.2 按资源类型分派

资源类型取自 `unitSource[i].type`（字典见 `docs/UOOC-双版目录结构底图.md` §7）：

| 类型 | `type` | 任务点 | 脚本行为 |
|---|---|---|---|
| 视频 | `10` | 一般是 | 等待播放完毕 → 等 `{等待时间}` → 点下一个内容 |
| 附件 | `50` | 一般不是 | 等网页加载完 → **自动点击打开附件（以非活动标签页方式打开，仍停留在当前课程页面）** → 等 `{等待时间}` → 点下一个内容 |
| 文本 | `60` | 一般不是 | 等 `{等待时间}` → 点下一个内容 |
| 讨论 | `70` | 一般不是 | **toast 提醒用户自己填写，并暂停连播**。若设置页开启「跳过讨论」→ 不提醒，直接等 `{等待时间}` → 点下一个内容 |
| 测验 | `80` | 一般是 | **检测是否完成**：<br>· 已完成 → 等 `{等待时间}` → 点下一个内容<br>· 未完成 → ① **开启 AI 答题**时：答题（见 [B 节](#b-ai-答题)）；② **未开启 AI 答题**时：toast 提醒用户自己答题，并**暂停连播** |

## A.3 设置项

| 设置项 | 形态 | 默认 | 说明 |
|---|---|---|---|
| **等待时间** | 数值（ms） | `5000` | **全局单一值，所有资源共用**；设置页可修改 |
| **跳过讨论** | 开关 | **开** | 开启后连播遇到讨论不再提醒用户，直接等 `{等待时间}` 后继续 |
| **AI 答题** | 开关 | **关** | 决定测验未完成时「脚本答题」还是「提醒用户并暂停」 |

**AI 答题的配置入口**：UOOC 设置页的 AI 答题项**只做指路**——引导用户去**全局设置页**修改
`API` / `Key` / `模型`（详见 [B.4](#b4-全局-llm-配置缺口)）。

## A.4 测验页的特殊处理（新版课程页）

> 用户原话：「其中有个特殊地方，若开启连播，新版本课程页打开答题时脚本应当修改当前页面地址成答题页，答题完毕后应当修改当前页面地址为课程页」

**前提（用户实测）**：新版课程页点击测验，**实际会打开新标签页**。

⇒ 脚本需要把「站点默认开的那个新标签页」改造成「在当前标签页内换地址」：

1. **进入测验**：脚本把**当前标签页的地址**改成答题页（而不是让站点开新标签页）。
2. **在答题页完成答题**。
3. **收尾**：脚本把**当前标签页的地址**改回课程页。

- 「改回课程页」时，是否要恢复到**当时那个节**的位置，还是回到课程首页？
- 旧版课程页是否也有这个「开新标签页」的问题？（原文只点名新版）

# B. AI 答题

## B.1 请求模板

- 一共 **3 套请求模板**。
- 三者的 **核心相同**、**命令输出格式相同**，**只有提示词不同**。
- **每次请求都随机抽取一套模板**。

❓待确认：
- **3 套提示词的正文由谁出？** 用户提供，还是我起草后你审？
- **随机抽取是有放回的吗**（同一道题的两次请求可能抽到同一套模板）？
  这会影响「两次答案相同」判定的强度——如果放回，两次都抽到同一套，答案一致几乎是必然的。
- **三套模板与输出格式各自长什么样**，需要正文才能实现。

## B.2 每道题的作答流程（**最多请求 4 次**）

```
请求 #1（随机模板）
请求 #2（随机模板）
  │
  ├─ #1 == #2  ────────────────────► 采用该答案，结束
  │
  └─ #1 != #2
       请求 #3（随机模板）
         │
         ├─ #3 == #1 或 #3 == #2 ──► 采用「出现 2 次的那一个」= 多者，结束
         │
         └─ #3 与 #1、#2 全不同（3 个答案互不相同）
              请求 #4（随机模板）
                │
                ├─ #4 与前面任一个相同 ► 采用多者，结束
                │
                └─ #4 仍与前面全不同（4 个答案互不相同）► 采用 #4（最后一次），结束
```

**规则一句话**：**少数服从多数；平局（全不同）就再要一次；最终仍平局就取最后一次。**

## B.3 输出格式与调用参数

**唯一已在文档里的既有口径**（来自旧参考脚本 `utils/quiz.js`，**不是**本项目已确认的规范）：

| 项 | 值 | 出处 |
|---|---|---|
| 返回格式 | `1. A\n2. B\n3. A,B`（多选逗号分隔，判断题 A=正确 B=错误） | [开发文档.md:724](开发文档.md#L724) |
| 解析正则 | `/^(\d+)\.\s*([A-Z,]+)$/`，失败回退 `/\d+\.[\s]*[A-Z]+/g` | [开发文档.md:725](开发文档.md#L725) |
| 调用参数 | `temperature: 0.3`，默认模型 `'gpt-3.5-turbo'` | [开发文档.md:726](开发文档.md#L726) |
| 请求 | `fetch` POST `{baseUrl}/chat/completions` | [开发文档.md:682](开发文档.md#L682) |

⚠️ **一处值得注意的矛盾**：旧脚本用的是 `temperature: 0.3`（低随机性）。
而本项目的「多请求取多者」是**自洽性投票**（self-consistency）——它要求模型输出**有多样性**才有意义。
`temperature` 太低时，两次请求几乎必然一致，投票逻辑形同虚设。

❓待确认：**`temperature` 用多少？** 是否沿用 0.3，还是为投票逻辑调高？

❓待确认：**答案如何回填并提交到 UOOC？** 原文未描述。

# C. 与既有设计的衔接

- **章节目录顺序**：来自 Angular 数据层的 `chapterList`（10 章 / 54 节），见 `docs/UOOC-双版目录结构底图.md` §5。
- **节级跳转**：可直接拼 hash `#/{cid}/{chapterId}/{sectionId}`（底图文档 §4.2）。
- **资源级跳转**：资源项无 `href`，只能调 `goSource(source, 'section')`（底图文档 §4.3）。
- **跨章行为**：~~设置页的 `nextScope`（`chapter` 止于本章 / `all` 跨章继续）~~ —— **已废除**。
  用户 m00971 原话：「不要限制连播范围了，一直播下去就好，把那个设置项完全移除」。
  ⇒ 连播**不设范围上限**，按目录顺序一路播到目录末尾（`finish('已到目录末尾')`）才停。
- **懒加载约束**：`unitSource` 只有当前节点被填充（底图文档 §8）。
  → 后果：**「下一个是什么类型」无法提前知道**，只能「走到那一项 → 读它的 type → 再决定动作」。
  本细则的流程恰好就是这个形状，**与懒加载天然兼容**。
