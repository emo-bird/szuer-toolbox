## 0. 这一轮改了什么（先读这段，知道该盯什么）

| 改动 | 肉眼能看出来的差别 |
|---|---|
| 连播从「点 DOM」改成「请求接口算下一个点」 | 点【开始接管】后**不再看到它去点目录树**；地址栏 hash 会自己变 |
| 标签页 `连播` → `接管`，按钮 `开始连播/停止连播` → `开始接管/停止接管` | 面板上那两处字变了 |
| 三个等待设置项从【接管】页搬到新的【等待】页 | 【接管】页**下面只剩按钮和一行状态**，看不到设置项了；多出一个【等待】标签 |
| 新增「全局等待超时」设置项（默认 30000） | 【等待】页多一行输入框 |
| `播完后停留(ms)` 默认值 3000 → 5000 | 【等待】页那一行的默认数字是 5000 |
| 走到测验但 AI 作答没开 / 视频两轮没记账 / 取目录连续三次失败 → 全屏弹窗 + 自动停 | 这些情况下会**弹一个大框**，点掉之后状态行是「已停止 —— …」 |
| 【监视】页「课程进度」下面新增**分层列表**（章 → 节 → 任务点，✅/⬜，当前项高亮） | 跑接管时监视页多出一个可滚动的三层列表，当前那一项左侧有竖条且加粗 |
| 「任务点」的判据改成 `learn_task_cnt > 0` | 目录里**只挂附件**的节不再被当成待办，接管不会卡在附件上 |
| 同一节里有**多个**任务点（视频 + 测验）时，逐个资源看完成状态 | 视频已打钩、测验没做的那种节，会**直接去做测验**，不会把整节当成没做完 |
| **交卷响应现在真的能截获了**（原来嗅探只装在页面顶层，而交卷是试卷 iframe 自己发的） | 交卷后不再出现「没截获到交卷响应」；Console 能看到 `HTTP 200` |
| 测验**不再重拉目录核实**，交卷响应直接当结论 | 交卷通过后立刻进下一个任务点，中间**不会**再多一次 `getCatalogList` |
| 交卷**没通过**时重做，且重答会把**上一轮其他投票**一起累计 | 重答给出的答案跟上一轮**不一样**了（以前是原样复读） |
| **试卷 iframe 上多了一层进度遮罩**（阶段 + 第 N/M 题 + 进度条 + 每题一行）与右上角【隐藏遮罩】 | AI 作答时试卷被一层半透明面板盖住，上面有实时进度；不想看可以点【隐藏遮罩】 |
| **【监视】页第一块改成【接管状态】**（状态行原文 + 提示历史） | 监视页最上面多出一块，带时间戳的提示一条条往下排 |
| **提示统一进 Toast 栈**，警告/错误类**不自动消失** | 右上角会冒提示；普通提示自己走，警告/错误带「×」要手动关 |
| 连续重复的同一句提示合并成 `文案（×N）` | 监视页里不会出现一屏一模一样的话 |
| 单次模型请求失败会**隔 2 秒重试**，最多 3 次 | 模型接口偶发抽风时，Console 里能看到「第 1/3 次请求失败…」然后自己重试 |
| 交卷请求返回**非 200**（502 等）→ 全屏弹窗 + 停止接管 | 弹窗文案里带 `HTTP 502` 这样的字 |

## 1. 前置条件

1. Tampermonkey 里装的是**构建号 #95** 的产物（产物头部「构建信息」那行会写 `v0.1.0#95`）。
2. 浏览器已登录优课联盟，能正常打开课程页。
3. **必须用旧版课程页**：地址栏是 `https://www.uooc.net.cn/home/learn/index#/...`。
   如果你打开的是 `/home/learn/new/<cid>#/...`，脚本会弹「切旧版」的提示 —— 那是预期行为，
   点提示里的按钮切过去再跑本清单。
4. 选一门**还有没做完的任务点**的课。本清单以劳动教育那门课（cid `2005836044`）为例；
   换别的课请自行对照条目里的「第几章第几节」。
5. **无存储前置**：本方案不记状态，任务起点每次都由接口现算，不需要清任何键。
6. 开着 Console（F12）—— 出问题时 Console 全文是主要线索。

### 3.7 🔴 交卷判读（2026-10-09 手测事故的验收）

> 上一轮手测：在 iframe 里点完【提交】、站点明明回了「没通过」，脚本却**完全没察觉**，
> 空转 5 分钟后报「答了 3 轮仍未通过」—— 实际只提交了 1 轮。
> 根因是**嗅探只装在页面顶层，而 `/exam/commit` 是试卷 iframe 自己发的**。
> 下面 4 条一起验收，**必须全过**才算这一批修好了。

| # | 动作 | 预期 | 失败时贴回什么 |
|---|---|---|---|
| 211 | 正常跑到一个测验，看 Console | 交卷那条日志里能看到 `HTTP 200`；**不该**再出现「没截获到交卷响应」这句 WARN | Console 全文 + 该请求的 Request/Response |
| 212 | 交卷**没通过**（分数 < 及格线）后 | 重做时 Console 里重答的日志带「累计 N 票里「X」占多数」这类字样，且**重答给出的答案与上一轮不同**（不再原样复读） | Console 全文 + 该题两轮的原始回答 |
| 213 | 3 轮都没过 | 弹**全屏框**，文案是「测验「…」答了 N 轮仍未通过」（N 是真实轮数，不是写死的 3） | 截图 + Console 全文 |
| 214 | 任何一次交卷请求返回非 200（502 / 500 等） | 弹全屏框，文案里带 `HTTP <状态码>`，并停止接管；**不要**把它当成「没通过」去重做 | 截图 + Console 全文 + 那条请求的 Request/Response |

### 3.8 看得见的进度（2026-10-09 第三份反馈的验收）

> 「各种状态提示要有 ToastStack」。下面 7 条一起验收。
> **不用等整门课**——跑到任意一个**测验**就能验 #215–#218、#221，**开始接管**就能验 #219、#220。

| # | 动作 | 预期 | 失败时贴回什么 |
|---|---|---|---|
| 215 | 接管走到一个测验、模型开始作答 | **试卷 iframe 上盖着一层遮罩**（不是面板里的弹窗），里面能看到：当前阶段文案、`第 N/M 题已定稿 · 任务 tid=…`、一根进度条、每题一行的状态列表 | 截图（连试卷区域一起拍）+ Console 全文 |

### 3.9 遮罩挂载时机修复（2026-10-09 第四份反馈的验收）

> 用户原话：「等 iframe 加载出题目的 dom 再放遮罩，不然被刷掉了」。
> 真因两条（都跟 iframe 的生命周期有关）：① 遮罩在**拉到试卷那一刻**就挂，而 iframe 可能还停在
> `about:blank`/刚导航 ⇒ 挂在**一份马上被换掉的 document** 上；② 原来「被抹掉就挂回去」写的是
> 缓存下来的 `doc.body`，iframe 一导航那份 document 就作废 ⇒ **挂了也永远看不见**。
> 现在：等 `div.queContainer` 出现才挂（超时 30 秒仍挂 + 记 warn），并且每次现取
> `frame.contentDocument`，250ms 巡检负责补挂与「换 document 后搬过去」。
> **#222 与 #227 是本批的重点**，#223–#226 是确认没把原有行为改坏。

| # | 动作 | 预期 | 失败时贴回什么 |
|---|---|---|---|
| 222 | ⭐ 接管走到一个测验 | 遮罩**在题目渲染出来之后立刻出现**，**不是**「先闪一下再消失」，也**不是**等 30 秒才出来。（日志里能看到「已开始等试卷 tid=… 的题目 DOM 出现」→「已给试卷 … 盖上进度遮罩」） | 截图/录屏 + Console 全文（尤其想知道：闪一下就没 / 一直不出现 / 30 秒后才出现，是哪一种） |
| 223 | 遮罩出现后停 10 秒 | 一直盖在试卷上不掉，进度条与「第 N/M 题已定稿」在动 | 截图 + Console 全文 |
| 224 | 手动点试卷里的题号或触发站点自己重渲染（随便点点） | 遮罩**不会消失**；日志里可能出现「遮罩被站点重渲染抹掉，已重新挂回」 | 截图 + Console 全文 |
| 225 | 走到「已点提交、等你过人机验证码」那一步 | 遮罩**照样自动让开**（不点隐藏也让开），验证码点得动；点完遮罩回来 | 截图 + Console 全文 |
| 226 | 点【隐藏遮罩】→ 再跑到下一个测验任务点 | 本次测验内不再出现；**下一个测验**重新出现（原有 F1 行为没被改坏） | 截图 |

### 3.10 视频播完直接进测验（2026-10-09 第五份反馈的验收）

> 用户原话：「移除原本的依赖 getCatalogList 的验证视频是否播放完毕的逻辑，检测到 ended 后等
> {播完后停留} 时间就**直接拼接测验路径进入测验页面**」。
> 现在：视频播完 → 等【播完后停留】(默认 5000) → **不重拉课程树、不核实**，直接把这一项记成
> 「已处理」，接着做这一节里排在后头的下一项（通常就是测验）；
> **整轮接管只在「一节里的任务点都做完」之后重拉一次**（用来刷新进度与终点）。
> **#228 / #229 是重点**，#230–#233 看有没有被带坏。

### 3.11 等题目渲染完再答题（2026-10-09 第六份反馈的验收）

> 用户原话：「开始答题需要等到 iframe 完全加载完才行，现在的太快了，网络较差题目还没显示出来，
