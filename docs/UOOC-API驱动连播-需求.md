## §0 为什么推倒重来

旧的「连播」是**靠点 DOM 推进**的：找目录里 `.active` 那一行，点下一行的 `div.basic`，靠 `ng-click` 触发站点自己的路由。实测下来这条路全是坑：

- 目录**懒渲染** —— 任何时刻 DOM 里只有「全部章 + 当前章节 + 当前节点资源」，点下一章得先把它展开。
- `.active` 有**三个来源**（节标题的 `div.oneline`、资源行的 `div.basic`、播放器自己的 `vjs-*`），播放器会抢。
- 完成标记 `complete` 只在 `is_task == 1` 时挂，普通视频可能永远没有。
- 点不动时标记写在一处、读在另一处，导致**纯微任务自旋把页面卡死**（已修，commit `e2cc7d3`）。

**新方案一句话**：改用**一次网络请求拿整棵课程树**（含完成状态），在脚本里算出「下一个未完成任务点」的 id，**自己拼 hash 跳过去**。DOM 只用来**读**（等视频 `ended`、等测验 iframe 出题），不再用来**点**。

## §A 三个已实测的前提

### A.1 数据源：一次请求拿到整棵树

```
GET https://www.uooc.net.cn/home/learn/getCatalogList?cid={cid}&hidemsg_=true
→ { code: 1, msg: "", data: [ 树 ] }
```

`data` 是 L1（章）数组，逐层 `children`。节点字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 节点 id（章 / 节 / 点）—— 拼 hash 用它 |
| `name` | 显示名 |
| `_level` | `1`=章、`2`=节、`3`=点 |
| `children` | 下一层 |
| `finished` | `1`=已完成、`0`=未完成 |
| `icon_list[]` | **非空 = 这个节点就是任务点**；`{ id, type, type_name, catalog_id }` |
| `task_id` | ⚠️ **在本接口里恒为 0**，不要拿它当测验 tid |

实测规模：10 个 L1、54 个 L2、40 个 L3。

**为什么 `task_id` 是 0 不影响本方案**：拼 hash 用的是 `sourceId = icon_list[0].id`，url 里根本不需要 tid；跳到测验之后，tid 白写在测验 iframe 的 `src` 里（`/exam/{tid}`），现成的 `quizTidOnPage()`（`src/sites/uooc/ai/index.ts:111`）已经在读它。**所以不必额外打 `getUnitLearn`。**

### A.2 路径模板

抄自站点自己的 ui-router 状态表（`local/capture/uirouter-states.json`，不是猜的）：

| 状态 | 模板 |
| --- | --- |
| `main` | `/:courseId` |
| `main.chapter` | `/{chapterId}` |
| `main.chapter.section` | `/{sectionId}` |
| `main.chapter.section.point` | `/{pointId}` |
| **`main.chapter.section.source`** | **`/{sourceId}/section`** |
| **`main.chapter.section.point.source`** | **`/{sourceId}/subsection`** |

于是两个常量模板：

```
任务点挂在「节」上（三级课程：章 → 节 → 资源）
    #/{cid}/{chapterId}/{sectionId}/{sourceId}/section

任务点挂在「点」上（四级课程：章 → 节 → 点 → 资源）
    #/{cid}/{chapterId}/{sectionId}/{pointId}/{sourceId}/subsection
```

## §B 节点模型：什么是「下一个任务点」

### B.1 任务点集合

遍历整棵树，**收集所有 `learn_task_cnt > 0` 的节点**（≡ 挂着 `10` 视频 / `80` 测验 的节点）。
不区分三级 / 四级 —— 差别只在拼出来的 hash 长什么样，处理逻辑完全一样。

> ⚠️ **不是**「`icon_list` 非空」。见 §B.5：`icon_list` 是**该节点挂的全部资源**；只挂附件（`50`）的
> 节点 `icon_list` 非空、但站点给的 `learn_task_cnt` 是 **0**、`finished` 永远是 0 ——
> 按旧口径收进来，主循环会永远卡在附件上。

### B.2 顺序 = 先序遍历

顺序就是树本身的顺序（`data` 数组顺序 → 递归 `children`）。**实现上不要依赖 `parent` / `pid` 字段往回找祖先**：递归时自己把「章 id、节 id」一路带下去，得到的就是权威的祖先链，拼 hash 直接用。

### B.3 起点：第一个未完成任务点

按 B.2 的顺序，取第一个 `finished` 不是 1 的任务点。判定一律用 `Number(finished) === 1`（这个接口里数字和字符串两种形态都见过）。

**为什么固定从第一个未完成开始，而不是从「当前停留在哪」开始**：用户拍板。少一个状态来源，少一类 bug。用户手动跳着看是另一回事 —— 手动操作后目录 hash 变了，但【接管】下次启动仍从头扫。

### B.4 跳转：改 `location.hash`

**不点目录、不调路由 API**，直接：

```ts
location.hash = `#/${cid}/${chapterId}/${sectionId}/${sourceId}/section`;
```

让站点自己的 Angular ui-router 接手（用户拍板「方案 A」）。

跳完要**等页面真的换过去**：hash 变化后路由是异步的，必须等目标节点对应的内容出现（视频 → `video` 元素；测验 → 带 tid 的 iframe），不能只 `await sleep(固定值)`。
（`WAIT_BEFORE_MS` 只是「改完 hash 后、开始等元素出现之前」的固定 sleep，见 §E.3。）

**四级路径照跳**（§F.1-1，选项 B）：hash 按 §A.2 的 `/subsection` 模板拼。
⚠️ 该拼法**尚未经真实页面验证**，是类推出来的 —— 用户 2026-10-08 已知悉并拍板接受。

### B.5 两段式：节点层找「节」，资源层找「点」

**2026-10-09 更正（实测，手测问题 2 的真因）**：一个节点可以挂**多个**资源 ——
实测节点 `473005785` `learn_task_cnt=2`，`icon_list` 是
`[1859489987 视频, 518085319 测验, 1552014835 附件]`，页面上是「视频 任务点 ✓」「测验 任务点」「附件」三行。
**节点自己的 `finished` 是这一节里所有任务点的汇总**（那个节点 `finished=0`，因为测验没做，
可视频早就打钩了）。所以拿节点级 `finished` 去判断「某个视频播完没」是错的 ——
这正是旧模型把已完成的视频认成「未播完」的原因。

于是模型分两层：

| 层 | 取数 | 判断什么 |
|---|---|---|
| 节点层 | `getCatalogList`（一次拿整棵树） | 哪一节还没做完；先序顺序 |
| 资源层 | `getUnitLearn`（只对**当前这一节**发，一次一个节） | 这一节里**哪个资源**还没完成 |

两层都不能省：只有节点层分不清同节里的视频与测验；只有资源层则要先遍历整棵树才知道顺序（67 个节 = 67 次请求）。

- **逐资源状态只有 `getUnitLearn` 有**，`getCatalogList` 不给。
- 资源层的「是任务点」判据：**有 `is_task` 字段就信它**，没有才按 `type ∈ {10,80}` 猜
  （实测 `is_task="1"` 只出现在 10/80 上、`60` 上是 `"0"`、`50` 上没有该字段）。
- 真正的跳转 hash 一律用 `sourceHash(cid, 节.ancestors, 节.nodeId, 资源.sourceId)`，
  **不要**用节点层的 `primaryHash`（那只是「第一个任务资源」的展示值）。
- `getUnitLearn` 顺手白给测验的交卷 tid（`task_id`，实测 `518085319 → 764270`）——
  但**页面里真正打开的那份 tid 更可信**（`quizTidOnPage()`），接口值只做兜底。
- 该接口的 `type` **数字与字符串混用**（同一份响应里 `'10'` 与 `50` 同时出现）⇒ 一律归一成字符串再比。

> 实测规模（2026-10-09）：课程 `2042342697` 的 67 个任务点里 **46 个是多资源节点**（2~3 个），
> 而课程 `2005836044` 的 66 个里 65 个只有 1 个资源 —— 所以旧模型在 A 课碰巧能跑、在 B 课必错。
> 两门课共 133 个带资源节点上，「任务点 = `type ∈ {10,80}`」与站点自己的 `learn_task_cnt` **不符 0 个**。

### B.6 「做完了没」以谁为准

**节点层以重新请求 `getCatalogList` 拿到的 `finished` 为准**，不看 DOM 上的 `complete` 类名。
每个任务点做完之后**重拉一次整棵树**（用户拍板「方案 A」）—— 比增量猜测简单得多，一次请求几 KB。

**但节点级 `finished=0` 不等于「还有活干」**：可能这一节的视频 / 测验在资源层看都完成了、
只是站点记账滞后（或这一节压根没有本站能处理的资源）。这时主循环必须
**记一条 `warn` 并跳过这一节**，绝不能原地空转 —— 否则又是一次死循环（§B.1 那条同理）。

## §C 一个任务点做完之后

⚠️ **分派用的是「当前这一节里第一个未完成的资源」的 `type`**，**不是** `icon_list[0].type`（§B.5）——
一个节可能同时挂着视频和测验，`icon_list[0]` 只是排最前那个，未必是还没做的那个。

### C.1 `10` 视频

1. 跳过去，等 `video` 元素出现并可用（**超时 = 全局等待超时**，见 §E.3 / §E.5）。
2. **完全看到底**，等 `ended` 事件。
3. `ended` 之后**等 `HOLD_AFTER_MS`（默认 `5000`）**（站点上报完成状态需要时间），再重拉 `getCatalogList`。
4. 看这个节点（**节点级汇总**）`finished` 是否变成 1：
   - 是 `1` → 按 §B.5 算下一个。
   - 仍是 `0` → **再等一个「全局等待超时」（默认 30 秒）**，**再重拉一次**。
   - 第二次仍然是 `0` → **全屏 `showModalAlert` 提醒 + 停止接管**。
   ⇒ **不重播**，最多多等一轮，上限明确。

> 二倍速 / 静音 / 防失焦这三个既有功能**保留**，行为不变。
> **不碰 `video.currentTime`**（§F.1-2 拍板）：站点带 `video_pos` 就从那儿续播，脚本不做任何
> 归零 / 恢复，「完全看到底」= 只管等 `ended`。

### C.2 `80` 测验

1. 跳过去，等**测验 iframe 加载完并且题目真的渲染出来**（用户 m06445 第 3 条）。
   **超时 = 全局等待超时（默认 30 秒）**。
   ⚠️ 这一条 **推翻了原先写死的 60 秒**（用户本轮拍板：**除 API 请求本身以外**的等待，
   一律统一到同一个设置项，见 §F.1-5）。
2. 超时 → **全屏 `showModalAlert` 提醒 + 停止接管**；按钮只有一个【知道了】，点完就停在那儿，等用户手动重开（用户 m06522 Q5 + 本轮拍板）。
3. 正常 → 取 tid：**优先 `quizTidOnPage()`**（页面里真正打开的那份才是要动的那份），
   读不出来才退回 `getUnitLearn` 白给的 `task_id`（§B.5）；两者都拿不到 → 停（只日志、不弹窗）。
   拿到后交给现有的 `runQuizAnswer(tid, host)`。
4. ~~答完重拉 `getCatalogList`~~ → **不重拉**（用户 m01884 Q5 = D1）：
   见下面 §C.2.1 第 5 条，「交卷响应本身就是结论」。

> **`AI_ANSWER` 关着的时候**（§F.1-6 拍板）：与第 2 步**完全同一套** —— 不尝试作答、
> 不跳过、不自动往下走，直接 `showModalAlert` + 停止接管，只有文案不同。
> 理由：静默跳过 = 在用户不知情的情况下漏掉整个测验；停下来让他选，是唯一不替他做决定的选项。

> 交卷仍然要走二次确认门禁（N1），这条不变。

理由：站点都判过了，再去拉树只是多一次请求、多一次「树还没更新时间对不上」的假阴性。

**新增的 HTTP 门**：`CommitResult` 多一个 `httpStatus`，配套 `isCommitHttpOk(result)`
（`200` 或 `0`=没拿到 才算走通）。**非 200 一律 `showModalAlert` + 停止接管** ——
因为 HTTP 500/502 的响应体里同样没有 `code`，会被判成 `unknown`，
而「没通过」和「这一发没走通」必须给用户看不一样的话。

**拉试卷**：`paper.ts` 的 `getTaskPaper` 超时 **20000 → 60000**（用户 m01884 报备 2 拍板）。

### C.3 `50` 附件 / `70` 讨论

### C.4 `60` 文本 / `0` / 未来新增

## §D 停止条件

| 触发 | 行为 |
| --- | --- |
| 没有未完成任务点了 | 停，状态行显示「全部完成」 |
