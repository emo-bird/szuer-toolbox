## 0. 这一版改了什么（用户的问题 + 两个候选路线）

**用户第十轮的原话**：「关闭课表自绘不应该有注入后的网页的绘制逻辑来绘制自定义课程吗，现在没有」。

**查证结果**（依据用户交来的课表页 HAR `local/capture/课表页1.har`）：
课表**确实**走 `POST elective/teachingTime.do` —— 渲染路径就写在那份 `curriculum.min.js` 里，
拿到 `e.dataList` 后交给站点自己的 `CVMyCourseTable.init($("#myCourseTable"), {…})` 画。
所以「站点自己画一份」这条路**本来就存在**，问题只是**我们没赶上**。

**真因是时序竞态**（用户自己发现的判据：**硬刷新能注入、普通刷新不能；F12 限速 3G 后又总能注入**，
且成功时必有 `[接管]` 日志、失败时必无）：暖缓存下站点 `teachingTime.do @75ms`，
而用户脚本装上接管在 **200ms** 之后；包装**只对之后新构造的请求生效**，那发原生请求完全静默。

**用户拍板拆成两条候选路线分别做**（原话「新建两个分支，一个做1+2，一个做3。先把3做了我看看效果，
再把1+2做了我看看效果」）：

| 路线 | 做法 | 状态 |
|---|---|---|
| **选项 3**（分支 `feat/bkxk-tt-refetch`，构建号 41） | 只**重新触发站点自己的初始化**，让它再请求一次（这次会经过我们的包装） | 用户已测：**成功救回来了，但自绘的位置错乱** ⇒ 暂时搁置 |
| **选项 1+2**（**本分支**，构建号 42） | ① 先加**诊断**（装上时刻 + 每条「没改写」的原因）；② 我们**自己补一次** `teachingTime.do`、合并自定义课程，再交给**站点自己的渲染器**重画 | 本轮待测 |

本版四条口径：
1. 补偿只在**六条同时成立**时发生：接管开着 / 自绘关着 / 本页还没补过 / 有启用的自定义课程 /
   站点画过的卡片里**一门我们的都没有** / 站点至少画了一张卡片。判据**刻意不看时钟**。
2. 触发点排在**自绘开关判断之前** —— 要的正是「关掉自绘也看得到」。
3. **每页只补一次**（补完会触发站点重绘，没有这道闸门就是新的死循环）。
4. 站点画过的课，**自绘不再画第二份**（两条路互补，不叠加）。

## 4. 通过判据

- **算通过**：#94 能看到判词；#96 关掉自绘后**仍然看得到自定义课程**、且**只有一份**。
- **一律算失败**（哪怕画面看着对）：
  - 同一门课出现**两份**卡片（叠加）；
  - 补偿那两行在**同一次页面加载里反复出现**；
  - 出现报错级日志、或站点课表被画坏（列错位 / 空白 / 点不动）。
- 允许的差异：站点自己画的卡片**样式**与自绘不同（这是预期内的）；**位置对得上**就行。
