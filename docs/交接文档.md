#### 4.4.1 `fuckuooc` 提炼结论

**它是「逆向成果」不是「同一站点的同类工具」**：它的答题是靠**截图问多模态大模型**，
视频内弹窗测验靠**暴力枚举选项组合**。

**A. 站点技术事实（直接可用）**

| 事实 | 依据 |
|---|---|
| **AngularJS 单页应用**；视频播放、章节切换、测验提交都依赖前端 JS 渲染 | `原理.md:28` |
| 播放器是**原生 `<video>`**，靠注入控制：`v.muted = true`、`v.playbackRate = 2.0`、`v.play()` | `原理.md:69-78` |
| **登录态 = 浏览器 cookie / session**（无 token 处理） | `原理.md:261`、`login.js` |
| **页面元素会嵌在 `<iframe>` 里**（登录框、部分页面元素）—— 定位要遍历所有 frame | `原理.md:284-296` |
| **站点有阿里云「智能验证」（验证码）**，依赖**浏览器指纹 + 行为分析**；提交试卷时也会触发 | `原理.md:30`、`原理.md:213` |

## 5. 关键决策与理由（理由比结论重要，别只抄结论）

### 5.1 请求出口：**同源走页面 `fetch`，跨域走 GM 通道**（Q-AE 起，后经 UOOC 补完）

- **同源请求**：`@grant unsafeWindow`（拿不到时退回 `globalThis.fetch`），
  `core/http` 用页面上下文的 `fetch`。
  **理由**：bkxk 的鉴权是「页面 cookie + `token` 头**缺一不可**」。页面 fetch 发出的
  `Origin` / `Referer` / `Cookie` / `Sec-Fetch-*` 与站点自身请求**逐字节一致**；
  `GM_xmlhttpRequest` 是扩展上下文发出的，这些头都要手动伪造、随时可能被识破。
- **跨域请求**（用户自己配置的大模型接口）**只能走 `GM_xmlhttpRequest`**（同样带
  `@connect *`）—— 页面 fetch 打外部域会被 CORS 拦。
- ⚠️ 所以 `@grant` 里**同时**有 `unsafeWindow` 与 `GM_xmlhttpRequest`，外加
  `GM_openInTab`。`tools/verify-build.mjs:16-27` 把这三条的**理由**写在注释里钉住了，
  **删任何一条之前先读那段注释**。
  （`GM_openInTab` 有个已知怪象：真机冒烟时日志报 OK、实际一个标签页都没开出来，
  目前无功能依赖它。）

### 5.2 限流：**200ms 从硬下限降级为软提示**（Q-AF，v0.10）

- 低于 200ms **只 `log.warn`，不改用户输入值**。`LIMITS.intervalMs.min` 仅防负数与荒谬值。
- **理由**：限流后果由用户自己的账号承担，脚本不该替用户否决显式选择。
  旧仓库红线 R2 在本项目**降级为软约束**。

### 5.3 风险开关：**🟠 / 🔴 的 `default` 一律写 `false`**（v0.10 收紧）

- 门禁由 `common/core/settings.ts` 的 `isEnabled` 统一兜底：未注册恒 `false`；
  从未设置过时**只有 `risk === 'safe'` 才取 `def.default`**，🟠/🔴 一律强制 `false`。
- 那为什么还要把 `default` 写成 `false`？因为**写 `true` 是死数据**，
  只会在后来人读代码时造成「这功能默认开着」的错觉。有测试逐条断言这个不变量。

### 5.4 旧数据迁移：**危险开关的旧值一律不搬**（批 1 拍板）

- `writeApiEnabled` / `hijackTimetable` / `hijackListConflict` 在新框架里是 🟠/🔴，
  按红线 **N1「必须经用户显式操作才生效」**，迁移**只提示、不写入**。
- **这是有意的行为差异**，不要为了「贴合旧版」改回去。
- 面板位置 `panelPos` / `panelCollapsed` **也不迁移**。迁移**不删旧数据**，且**只跑一次**。

### 5.5 日志等级：**读取期过滤**（Q-AC，v0.9）

- `push()` 一律入 500 条环形缓冲；`entries()` / `dump()` 按当前等级过滤。
  这样切到更低等级**能看到该页打开前的历史日志**。
- 代价：debug 日志多时会把老信息挤出环形缓冲 —— 刻意的取舍。
- ⚠️ 模块日志**只进【日志】页，Console 里看不到**。

### 5.6 demo 演示适配器：**保留到阶段 3 结束再删**（Q-AD，v0.9）

- `src/sites/demo/index.ts` 是 `localhost` 适配器，阶段 2/3 完成前它是唯一能验证
  UI、分派与风险门禁的**活体样本**。URL hash 带 `sztb-demo` 可强制注入。
- ⇒ **接手 UOOC 的人有活体样本可用**：改 `SiteAdapter` 契约时先拿 demo 冒烟。

### 5.7 架构铁律：`common/` 与 `sites/` 的依赖方向

1. **`common/` 不得 import `sites/`**，只能 `sites/ → common/`。
   公共组件需要站点信息时走**依赖注入**：`setSiteNameResolver`、`setStatusProvider`、
   `setCurrentSiteResolver`、`setOwnSettingsTabResolver`。
   违反这条最常见的诱因是「公共设置页想遍历站点列表」——
   正解是 `core/settings.ts` 的 `registeredSiteIds()`，不是去 import registry。
2. `sites/` 内各站点**互不 import**；跨站点数据走 `common/core/storage`。
3. 站点模块**不直接操作悬浮窗 DOM**，只通过 `TabRegistration` 声明式注册。
4. UI 完全自研，**不引入任何 UI 库**（Bonsai-kit 已否决，留档在需求文档 §7.1.1）。

### 5.8 测试策略：**只做档 1**（用户确认）

- 档 1 = 纯函数冒烟（Node assert，秒级，每次改完必跑）。
- **不做档 2**（接口契约冒烟）。
- **风险接口零自动化测试**，改由用户按固定格式手测（动作 / 预期 / 失败贴回什么 / 成功回什么）。
  清单骨架与写法见 `docs/手测清单-模板.md`。

## 7. 已知的坑（写代码前必读）

### 7.1 沙箱与工具链

1. **DSH 沙箱禁止「node 用管道 spawn 子进程」**（`EPERM`）。所以：
   - `npm install` 必须加 **`--ignore-scripts`**；
   - esbuild 的 **JS API 用不了**（`ensureServiceIsRunning` 会 spawn 服务进程）；
   - `build.mjs` 只能 `spawnSync(exe, args, { stdio: ['ignore', outFd, errFd] })`（**fd 重定向**），
     不能 `{ encoding: 'utf8' }`（走管道，EPERM）。
   - 这个限制**随沙箱档位变化**：切到 `danger-full-access` 后命名管道解禁。
     遇到 `spawn EPERM` **先确认当前档位**，别当成固有缺陷。
2. **Node 24 的类型擦除是 strip-only** ⇒ **全项目禁止 TS 构造函数参数属性**
   （`constructor(readonly x: T)`），否则 `node tests/run.ts` 直接报
   `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`。
3. **注释里不要出现带 `*/` 的 glob**（例如写 `src/**/*.ts` 会提前闭合块注释）。
   曾因此一次刷出满屏 `TS1109` / `TS1127`。

### 7.2 pwsh（这台机器上 `pwsh` 实际是 Windows PowerShell 5.1）

4. **双引号字符串里的 `$(...)` 会被 PowerShell 当命令执行**。
   批量文本替换最稳的做法是**写 Node 脚本文件**，或者用 `edit` 工具。
   用 pwsh 做替换还有一个坑：行内已有前缀时 `.Replace()` 会**二次加前缀**。
5. **`^{tree}` 会被当花括号展开吃掉**：`git rev-parse 8d033f0^{tree}` 报
   `fatal: ambiguous argument 'dAByAGUAZQA=': unknown revision`。
   **一律加单引号**：`git rev-parse '8d033f0^{tree}'`。
6. **git 输出走 stderr 会被 pwsh 判成错误**：`git checkout` 成功时打印
   `Switched to branch '…'` 到 stderr，pwsh 会显示 `NativeCommandError` 且
   `$LASTEXITCODE` 为 1。**别把这个 exit 1 当成命令失败**，用后续查询核实真实状态。
7. **写文件要防 BOM**：pwsh 5.1 的 `Set-Content -Encoding utf8` **会加 BOM**
   （`utf8NoBOM` 这个枚举值在 5.1 上不存在）。要写无 BOM 文件用
   `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`。
   **commit message 一律用单引号 here-string**（`@'…'@`，禁插值）落临时文件 + `git commit -F`。
8. `edit` / `write` 工具偶发 **`ReplaceFileW EIO (Win32 1175)`**（文件被占用）——
   文件**没坏，重试即成功**。重试前先用 `Get-Item .Length` + 行数 + `Select-String` 确认没写坏。
9. **读中文文件时，pwsh 控制台输出会乱码**（呈 GBK 样）。
   让 Python 打印中文要加 `$env:PYTHONIOENCODING='utf-8'`；
   或者把结果写到文件再用 `read` 工具读。**抓包 HAR / 大文档一律先落盘**。

### 7.3 上下文管理（**本机特有，不看会吃大亏**）

10. **任何 `read` / `grep` 的结果超过约 2K tokens 就会被自动落盘**，你只会拿到一行
    `📦 [acp-stored #mNNNNN …]` 占位符。补救靠 `acp_retrieve("mNNNNN")`，而它的行为**分两档**：
    - 原文 **< 4K tokens** → **内联返回全文**（好用）；
    - 原文 **≥ 4K tokens** → 只**导出到一个 .txt 文件**，而**再去 `read` 那个文件又会触发一次落盘**，
      于是陷入死循环。
    ⇒ **要读长文档，必须切成 ≤ 100 行的小块去 `read`，然后立刻 `retrieve` 那一小块**。
    一次性 `read` 200 行以上 = 拿不到内容。
11. **`lean_agent` 走本地模型不可用，走在线模型可用**（2026-10-08 实测）：
    - 用 preset 默认的本地模型（`local-llm` / `ornith-1.5-9b-…`）调用，**连续两次**都直接
      `Error: lean_agent run failed`，子代理根本不启动 ⇒ **本地模型这条线暂时别用**。
    - 显式传 `provider: "deepseek-official", model: "deepseek-flash"` **能正常跑**
      （用它扫完了 `local/` 全目录、查清了 `type 60` 语义与 `/subsection` 的实证情况）。
    - 教训：`lean_agent` 的失败**未必是 prompt 的问题**，先怀疑模型/服务端。
      委派时**务必写明「只回 N 字」的输出上限**，否则容易撞上限。
12. 项目文档（需求 / 开发 / 交接 / 手测清单）**禁止整份读**：先 `grep` 定位，再用
    `read` 的 `offset` / `limit` 只读命中段落。
13. **抓包文件里的隐私（真实姓名 / 学号 / 手机号）绝不喂云端模型** —— 只走本地模型。
    UOOC 的抓包**必定含学号与姓名**，这条对阶段 3 尤其硬。

### 7.4 项目自身的坑

14. **`header` 的 `@match` 与注册表是两份必须同步的清单**，不一致时的表现是
    **完全静默**（UOOC 上脚本「一行日志都没有」排查了很久）。
    现在由 `tools/verify-build.mjs` 的一条自检 + `tests/suites/sites-registered.test.ts` 钉住。
15. **回归测试必须走被测的那条真实路径**。`sites-registered` 套件初版自己
    `registerAdapter()` 搭舞台，用「注释掉真实注册那行」做反向对照实验时**依然全绿**
    （测试只是在测自己）。改成调用真正的 `registerSites()` 后，同样实验立刻 6 项失败。
16. **bkxk 的业务码不能只看 `code`**：被限流时站点返回 `code=0`「请求过快，请登录后再试」，
    `code=0` 不在映射表内，靠 **msg 含「登录」** 落兜底分支。已知映射：
    `1` 成功 / `2` 业务拒绝（`msg` 即原因）/ `302` 或 msg 命中 `登录|认证` = 登录失效。
    ⚠️ **UOOC 的业务码体系完全是另一套，不要照搬这条的结论，但要照搬这条的教训。**
    （已知 UOOC 的 `getCatalogList` 成功是 `code: 1`；交卷未通过是 **`code == 110`**。）
17. **Shadow DOM 的事件 `target` 重定向**：事件传到宿主以外时 `target` 变成宿主元素。
    **往页面里注入元素、或与站点脚本抢事件时，都要记得这件事**：
    站点看到的事件源不是你以为的那个元素。
18. **`dist/.build-no` 不随 git**（已 gitignore），所以本地计数可能**领先于产物里
    记录的构建号**。判断「用户装的是哪一次构建」**以产物头部那行 `构建信息` 为准**。
19. `dist/szuer-toolbox.user.js` **是随 git 提交的**（自动更新靠 raw 链接直接取它），
    改代码后要记得一起提交产物；但**纯构建号变动导致的 churn 已刻意不提交**。
20. ⚠️ **`docs/需求文档.md` 与 `docs/开发文档.md` 的版本号各自独立演进**，不要配对读；
    死分支用过的号会跳号，属于正常现象。
