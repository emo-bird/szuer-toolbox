> **被测对象**：`dist/szuer-toolbox.user.js`（v0.1.0，构建号 **#28**；首轮是 #25，第四轮显示修正为 #27，第五轮卡片改动态高度后为 #28）

> **回话格式**：全过回「OK」；某条不过回「第 N 条：<现象>」+ Console 报错全文 + 截图
> **时间紧时**：先跑 **7、8、9、12**（点击只入队、按钮切态、重扫不叠块 —— 这四条是这批的核心）
> **与 §8.2 的对应**：本文件第 N 条 = `docs/开发文档.md` §8.2 的第 **N+35** 条（即 1→#36 … 16→#51）

## 0. 这一轮改了什么（先读这段，知道该盯什么）

| 改动 | 因此要盯什么 |
|---|---|
| 每个教学班旁注入一块「教学班ID + 添加抢课 + 添加监控」 | 两种页面形态（卡片 / 列表）都该有；**一张卡里两个教学班要各有一块**，不能都挂到第一个 id 上 |
| 列表类页签改成 flex 并追加一列「抢课模块」 | 表格**不能错位**：每列内容仍在自己的表头下面 |
| 点击按钮只写本地队列，不发请求 | Network 面板**不该有新请求**；按钮要变「已加抢课」/「移除监控」 |
| 站点重绘后靠 MutationObserver 补注入 | 展开/收起卡片、切页签、刷新后**不能出现两块叠在一起** |
| 新增 🟢 开关「列表注入（教学班ID / 抢课按钮）」，默认开 | 关掉后已注入的块要**立即**消失（不用刷新页面） |
| 只改了 bkxk 选课页 | 其他页面（含 bkxk 课程表页、其他站点）**不该有任何蓝框** |

## 1. 前置条件

- 装本分支构建出来的 `dist/szuer-toolbox.user.js`（头部构建号应为 **#28**）。
- 已登录 bkxk，能打开选课页（`…/default/grablessons.do…`）。
- 建议先开 DevTools Console 并切到 Network 面板（第 7~10 条要用）。
- **本项目启动期诊断走 `console.info`**，`console.debug` 会被 Edge 默认过滤 —— 看日志前先确认没开过滤。
- 本轮**不需要**清存储；如果你想测「重复加入」，第 8 条会自己覆盖。

### 7.1 结果（已回）

用户原话：「列表式页面中添加抢课和添加监控两个按钮没有在同一行，导致行高变大 /

⇒ **第 1–16 条功能面全部通过**；四条反馈都是显示问题（+ 一条新需求），已修（提交 `97b8a03`）：

| 反馈 | 根因 | 修法（用户拍板口径） |
|---|---|---|
| 两个按钮不同行、行高变大 | `.sztb-bkxk-ops` 是 `flex-wrap: wrap`，150px 的列里两个按钮折行 ⇒ 一行变三行 | 改 `nowrap` + 按钮 `white-space:nowrap`，并整体压缩块的 margin/padding/line-height；排布按你选的 **B**：教学班ID 单独一行、两按钮同行 |
| 表头「抢课模块」后有没作用的顺序指示 | 站点给表头单元格挂的通配规则（`::after` / 背景图）连我们这份一起命中 | `.sztb-bkxk-head` 上清掉 `::before/::after` 与 `background-image`（表头文字按你选的保持不变） |
| 卡片页部分卡片内容溢出到卡片外 | 注入点原本在 `.cv-caption-red` 之后，而它在 `div.cv-info > h5 > div.cv-caption-red`，等于把块塞进站点单行容器 `<h5>` | 按你指定改插 **`.cv-info` 的第一个子位置**（教师名那一行**之上**） |
| 卡片页一屏显示太少（新需求） | —— | 按你选的「压卡片内部间距」：只作用于**含我们注入块的那张卡**（`:has(> .sztb-bkxk-block)`），压 `.cv-info` padding、`h5` 与说明行 margin/line-height、`.cv-operate` margin |

## 8. 第五轮结果与复测（构建号 #28）

### 8.1 结果

用户原话：「**卡片内容依旧溢出卡片外 / 卡片内容行高没有减少 / 其他测试符合预期**」，
并给出方向判断：「**我认为改成动态行高更合适，因为部分卡片溢出部分不溢出**」。

| 反馈 | 根因（**真机采样定论**，不是猜的） | 修法（用户拍板 A 方案） |
|---|---|---|
| 卡片内容依旧溢出卡片外 | 站点把 `.cv-course-card` **高度写死 210px**（13 张卡计算高度全是 210px、`overflow: visible`），而卡内 `.cv-info` 实测 **234–254px** ⇒ 内容从卡片下沿漏出。**各卡元素数量本就不同**（有的多一行 `.cv-caption-text` / `.cv-caption-red`），所以「部分溢出部分不溢出」 | 含我们块的卡片改 `height: auto !important; min-height: 210px`（站点原值兜底），卡片按内容长高 |
| 卡片内容行高没有减少 | **不是规则没生效** —— 采样显示紧凑规则命中 13/13、`h5` 的 `margin`/`line-height` 都是我们的值；而是卡片总高由站点那个固定值决定，**不跟内容变**，所以屏幕上看不出差别 | 在动态高度的前提下，同时**缩小卡片内容上下左右边距**：卡片 `padding` 16px → `8px 10px`，卡片内容区上下 margin 统一清零（站点给每个子 div 挂了 `margin-top: 4px`） |
| （顺带否定）我们的块撑宽了卡片 | ❌ 采样实测块宽 212 = 容器宽 212，两个按钮各 57px 就位 —— **横向没有问题**，溢出全是纵向的 | —— |

> ⚠️ **取舍（已告知用户）**：带注入块的卡片会比站点原样**略高**（我们的块本身就占 40px 高），
> 所以「一屏更多卡片」这个目标**放弃**，「不溢出」优先。若你希望回到「一屏更多」，那要走 A+ 方案
> （把教学班ID 截短显示、与按钮挤成一行），需要你另行拍板。
